# 제조 AI Agent 실습 특강 구성안

작성: 2026-11-20 KST · 갱신: 2026-11-21 KST · v0.2 · 상태: **설계 제안**

구현·배포의 상세 기준은 [전체 제작과 배포 설계](MANUFACTURING_WORKSHOP_E2E_BLUEPRINT.ko.md)를 따른다. 이 문서는 강의 목표와 활동 구성의 요약이다. 아래 다지점 도면 계측·키팅은 추가 촬영 후 확장할 목표이며, 현재 자료로 만드는 기본 수업은 전자 조립 / 계측 판독 / 기계 조립·재검수의 세 팩이다.

자료 준비 후속: [영상 기반 원본 자료 모음](../scenarios/index.json)에 영상 7개·사진 2개, 원본 상태 PDF, 절차·오류 주석, QR 부품표, 계측 XLSX를 모았다. [미리보기](../index.html)에서 확인할 수 있다. 이는 원본 확보·장면 표본 검수 단계이며, 아래 실습 앱의 구현이나 모델 검증을 뜻하지 않는다. 동일 제품의 다지점 계측과 키팅·포장 자료는 추가 준비가 필요하다.

4시간 중 소개 35분, 실습 165분, 마무리 10분, 휴식 30분으로 구성한다. 수강생은 기존 텀블러 품질관리 수업에서 익힌 문서·사진·검사 이력·DB를 확장하여, 회사 기준을 불러오고 작업을 관찰하며 질문과 보고서까지 연결하는 작은 제조 Agent를 실행한다.

현재 확보한 영상으로 만드는 핵심 실습은 **전자 조립 작업 지원 / 계측 판독·확인 / 기계 조립·부품 교체 후 재검수**의 세 개다. 동일 제품의 도면 기반 다지점 검사와 키팅·포장은 신규 촬영 후 확장한다. 모든 예시는 같은 프로그램, 같은 문서·DB·이벤트·보고서 구조를 사용하며 데이터와 규칙을 바꾸어 실행한다.

이 문서는 새 강의용 구현, 모델 실행, GPU 실험 또는 GitHub 게시 완료를 뜻하지 않는다. 현재 프로젝트의 GPU 중단 지시를 유지한다. HTech 문서·영상·프레임·음성·추론 결과·파생 ontology를 공개 실습 자료에 사용하지 않는다.

## 1. 수업의 완성 기준

수강생이 각 단계에서 결과를 확인하고, 일부 입력을 바꾸어 결과가 달라지는 이유를 설명할 수 있어야 한다.

1. 예제 SOP·BOM·도면·검사표에서 어떤 값이 추출되었는지 원문과 대조한다.
2. 회사·제품·공정 이름 또는 바코드로 적용 문서 버전, 작업 순서, 검사 기준을 불러온다.
3. 영상의 관찰 결과와 규칙 판정을 구분하고 관련 증거 사진을 확인한다.
4. 불명확한 장면이나 수치에 대한 질문에 답하고, 답변의 출처와 반영 결과를 확인한다.
5. 검사 누락·불합격·미확인 항목을 포함한 검수조서와 작업 보고서를 저장한다.
6. 허용 범위, 부품 수량, 제품 코드 또는 답변을 바꾸고 새 실행 결과를 비교한다.

정해진 결과는 항상 ‘합격’을 의미하지 않는다. 예제에는 정상, 명확한 불일치, 정보 부족, 추가 확인 후 해결 경로가 모두 있어야 한다. 실습 완료와 제품 검사 합격은 구분한다.

## 2. 공통 구조와 AI를 사용하는 지점

```text
회사 자료: SOP.pdf / BOM.csv / 검사기준.xlsx / 도면.pdf·svg / 장비정보.csv
  → 문서·표 추출
  → 명시적인 필드 매핑, 단위·ID·참조 검사
  → 버전이 있는 회사 데이터와 SQLite DB
  → 공정·제품·작업 선택 또는 제품 바코드
  → 해당 작업 순서, 규칙, 도면, 부품, 장비 정보 로드
  → 사전 촬영 영상과 시간순 관찰 이벤트
  → 도구 선택: 장면 관찰 / 원본 확대 / 바코드 / OCR / 질문
  → 대상·시점·적용 조건 검증 및 규칙 판정
  → 질문, 답변 확인, 추가 증거, 재검사
  → 상태와 증거 기록
  → 도면 위 측정 기록 + 검수조서 + 작업 보고서
```

| 기능 | 기본 구현 방향 | 생성형 모델 사용 |
|---|---|---|
| 텍스트 PDF·표 추출 | 기본 웹앱은 PDF.js와 명시적 필드 매핑, CSV 읽기; Python 제작 경로는 pdfplumber | 없음 |
| 회사 정보·ontology 구성 | 고정 스키마, 명시적 매핑, 출처 및 버전 검증 | 기본 실습에서는 없음 |
| 공정명·제품코드 조회 | 별칭을 ID로 매핑하고 매개변수화 SQL 실행 | 없음 |
| 작업 순서·적용 시점 | DB의 의존관계와 상태 전이 규칙 | 없음 |
| 바코드·QR | 브라우저 WASM 디코더 후보; 실제 영상에서 검수 후 활성화 | 없음 |
| 영상의 동작·관계·가림 관찰 | 기존 Qwen 계열 관찰기 또는 저장된 관찰 응답 | 필요 시 VLM |
| 디지털 계측기 문자 | GLM-OCR 주 후보, PP-OCRv6 medium CPU 대안 후보; 새 자료에서 선택 | 전용 OCR 모델 |
| 아날로그 버니어 | 주척·버니어 눈금 결합, 관측 가능성 검사 | 일반 OCR만으로 해결하지 않음 |
| 수치 비교·누락 검사 | 10진수 기반 값/단위 검증과 명시적 규칙 | 없음 |
| 한국어 확인 질문 | 사전에 작성한 질문 템플릿 | 기본 실습에서는 없음 |
| 답변 처리 | 질문에 연결된 입력, 단위·대상 확인; ASR은 선택 | 음성 인식 모델은 선택 |
| 보고서 | 확정된 기록으로 HTML/PDF/CSV/JSON 생성 | 없음 |

LLM 사용을 줄이는 대상은 특히 회사 기준의 확정, 반복 조회, 수치 계산, 상태 관리, 보고서 사실 서술이다. 영상 인식까지 결정적이라고 주장하지 않는다.

### 문서 추출과 ontology의 범위

기본 문서는 검색 가능한 텍스트 PDF와 규칙적인 표로 제작한다. 표의 위치·열 이름·단위 표기·문서 버전을 고정하고, 추출 결과를 스키마와 원문 참조로 검증한다. 읽지 못한 값을 기본값으로 채우지 않는다. 임의의 스캔 문서나 복잡한 도면을 완전히 자동 구조화하는 기능은 기본 수업 범위가 아니다.

설치 없는 수강생 경로는 PDF.js와 템플릿별 필드 매핑을 사용한다. `pdfplumber`는 강사용 Python 제작·검수 경로의 후보로 남긴다. 복잡한 레이아웃이나 스캔 문서는 Docling의 문서 파이프라인을 선택적으로 검토하되, OCR·레이아웃 추론이 들어가므로 순수한 규칙 처리와 구분한다. 동일 자료의 반복 실행을 재현하려면 입력 파일, 추출 설정, 의존성 버전과 정규화 결과를 함께 고정해야 한다.

NVIDIA Auto Ontology는 기존 구조화 DB 위에 업무 용어, 관계와 SQL 속성을 구성하고 질의를 지원한다. ontology 생성과 질의에는 모델이 사용된다. 따라서 기본 실습의 `PDF → 확정된 DB` 단계에 필수로 넣지 않는다. **완성된 예제 DB를 연결해 의미 계층과 질의를 보여 주는 선택 심화**로 배치한다. 자체 `ontology.yaml`과 Auto Ontology의 가져오기 형식이 같다고 가정하지 않고, 심화 구현 시 변환·버전을 확인한다.

기본 실습에서 ontology는 제품–부품–공정–작업–검사 위치–기준–증거의 명시적 관계를 뜻한다. 자연어로 매번 SQL을 생성하지 않아도 공정 이름 선택과 관계 조회를 충분히 시연할 수 있다.

공식 참고: [pdfplumber](https://github.com/jsvine/pdfplumber), [Docling](https://docling-project.github.io/docling/), [NVIDIA Auto Ontology](https://github.com/NVIDIA/auto-ontology), [ZXing-C++](https://github.com/zxing-cpp/zxing-cpp), [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), [WeasyPrint](https://doc.courtbouillon.org/weasyprint/stable/index.html).

### 공통 데이터 구조

| 데이터 묶음 | 주요 내용 |
|---|---|
| 회사 기준 | 회사·사업장, 제품, 문서 버전, 원문 위치, BOM, 공정, 작업, 선후관계 |
| 검사 조건 | 기준 ID, 대상, 적용 단계, 허용 값·단위, 필요한 절차, 허용 증거 |
| 도면·장비 | 도면 버전, F01~F04 검사 위치, 도면 표시 좌표, 장비 ID, 해상도·단위·눈금 정보 |
| 실행 기록 | 작업 세션, 제품 개체, 시도 번호, 관찰 시각, 현재 작업과 예상 작업 |
| 증거와 대화 | 원본 영상·프레임, 읽은 원문, 측정 제안, 질문 ID, 답변, 추가 확인 |
| 판정과 출력 | 원시 관찰, 규칙 판단, 최종 상태, 보류 사유, 재검사 관계, 보고서 |

`회사명 + 제품 버전 + 공정 ID`가 기준 묶음을 선택한다. 공정 이름이 중복되면 사용자에게 해당 제품·버전을 선택하게 한다. 새 문서 버전이 추가되어도 진행 중인 세션의 기준은 조용히 바뀌지 않는다. Markdown은 확정된 데이터에서 만드는 설명 문서다.

## 3. 실습 모드와 재현성

| 모드 | 실제로 실행하는 부분 | 화면 표시 |
|---|---|---|
| 기본 재현 | PDF·표 추출, DB, 바코드, 규칙, 질문·응답, 상태, 보고서. 무거운 VLM은 저장된 실제 응답 사용 가능 | 저장된 모델 관찰 사용 |
| 실제 인식 | 동일 입력에서 OCR/VLM을 새로 실행하고 원시 응답부터 기록 | 새 모델 실행 |
| 제어 연습 | 작성된 관찰 이벤트나 수강생의 수동 입력으로 오류·재작업 경로 확인 | 교육용 이벤트 / 수동 입력 |

기본 실습에서는 문서·DB·검증·보고서가 실제로 동작해야 한다. 바코드와 준비된 선명한 디지털 계측 사진은 CPU 실인식을 우선한다. VLM을 학생별로 설치하지 않고 필요하면 강사용 공용 서버에 연결한다. 공용 서버가 준비되지 않아도 재현 모드로 수업을 끝낼 수 있도록 한다.

저장 응답은 실제 생성 출처와 모델·프롬프트·프레임 해시를 포함한다. 변경된 영상·프롬프트에 오래된 응답을 새 예측처럼 붙이지 않는다. 실습용 정답은 모델 입력에서 제외한다. 모델 응답 실패나 인식 불확실성을 숨기고 성공 응답으로 교체하지 않는다.

숫자 판독과 허용 범위 비교는 분리한다. 같은 원본 판독을 유지한 채 수강생이 교육용 검사 기준 버전을 변경하면 규칙 결과가 달라질 수 있다. 영상 질의에 기준 자체를 포함한 경우에는 그 기준 변경이 모델 입력도 바꾸므로 재추론 또는 명시적인 제어 실습으로 처리한다.

학생 화면은 실행 버튼, 원문/영상, 추출된 표, 판정 이유, 질문, 보고서 중심이다. JSON·SQL은 펼쳐보기로 제공한다. 노트북은 ‘셀 순서대로 실행’하는 보조 경로로 두고, 직접 코드를 작성해야만 진행되는 부분은 최소화한다.

## 4. 실습 1 조립 작업 지원

### 목표와 자료

하나의 조립품에 대해 준비 영상과 연속 조립 3~4단계, 최종 확인을 보여 준다. 부품 이름과 전체 순서는 SOP/BOM에서 로드하고, 현재 실제 작업은 영상과 대조한다. 준비 장면 하나로 회사의 전체 공정 순서를 추론했다고 설명하지 않는다.

첫 개발 사례는 EgoOops 전자 회로 조립으로 한다. 원본8단계와 정상 주석·오류 주석 영상이 있어 문서부터 질문·보고서까지 연결하기 좋다. 일반 기계 조립은 IndustReal 차체·브래킷·바퀴 축의4작업군으로 별도 제공한다. 아래 표는 조립 실습의 공통 패턴이며, 실제 조건과 구간은 상세 설계의 시나리오 A/C를 따른다.

| 구간 | 관찰 및 실행 | 의도한 학습 결과 |
|---|---|---|
| 준비 | 작업지시 선택, 부품·공구 목록과 준비 장면 대조 | 잘못된 공구 또는 준비 미확인 항목 확인 |
| 조립 1 | 베이스/프레임 배치와 연결 | 기대 작업과 관찰된 작업을 함께 표시 |
| 조립 2 | 축·부품 모듈 장착 | 부품이 보이는 것과 지정 위치에 연결된 것 구분 |
| 조립 3 | 고정부·커버 장착 | 현재 단계의 조건을 검사; 아직 하지 않은 다음 단계는 ‘미도래’ |
| 추가 확인 | 손에 가려진 연결부에 질문 | 보류·추가 사진·답변을 같은 작업에 연결 |
| 마감 | 손을 뗀 최종 상태와 남은 항목 확인 | 완료 여부와 미확인 항목이 포함된 보고서 생성 |

‘체결이 잘 되었는가’는 확인 가능한 항목으로 구체화한다. 예: 지정 위치의 고정부가 보이는지, 커버 간격과 안착 상태가 기준 이미지에 부합하는지. 보이는 나사 머리만으로 토크·내부 나사산·강도를 확인하지 않는다. 토크 기준이 있으면 그 장비 측정이 별도로 필요하다.

### 질문과 증거

예시 질문: “오른쪽 고정부가 손에 가려져 있습니다. 손을 떼고 고정부가 보이도록 보여 주세요.”

최소 한 건은 질문이 생성되는 시점에 한국어 안내 음성을 실제로 재생한다. 미리 녹음한 안내 또는 준비된 TTS를 사용하며, 해당 질문 카드와 같은 질문 ID를 기록한다. 마이크 답변의 실시간 전사는 선택 기능으로 두되, 질문 음성 재생과 답변 연결은 기본 교재에 포함한다.

수강생은 `추가 장면 보기` 또는 `답변하기`를 실행한다. 교재의 후속 영상은 **사전 촬영된 추가 증거**로 표시한다. 텍스트·녹음 답변을 실제 영상 재촬영으로 표시하지 않는다. 답변은 원래 질문·대상·시도에 연결하여 저장하고, 시각적 확인이 필요한 조건은 추가 사진/영상 이후에만 다시 판정한다.

같은 원본 연속 촬영을 여러 클립으로 나누었다면 원래 시각과 동일 작업물 정보를 유지한다. 서로 다른 사람·제품의 영상을 이어 붙여 한 작업물의 완성 증거로 사용하지 않는다. 필요하면 별도 작업 세션으로 표시한다.

### 수강생이 바꾸는 것과 산출물

- 필요한 공구 또는 부품 수량 한 항목 변경.
- 가림 장면에 대한 질문 선택 및 추가 증거 확인.
- 준비 → 진행 → 최종 확인의 기록과 남은 조건 확인.
- 조립 검수조서, 작업 수행 보고서, 중요 사진과 이벤트 로그 저장.

현재 EgoOops S1790005 약121초와 S1790010 약227초, IndustReal 조립184.5초와 유지보수136.7초의 전체 원본을 확보했다. 원본 절차·오류 주석과 부품·상태 PDF, 교육용 작업군 초안은 [영상 자료팩](../scenarios/index.json)에 있다. 이는 자료 준비 상태이며 새로운 모델 인식 결과는 아니다.

전자 조립 두 영상은 별도 실행이다. 오류 주석이 없는 영상도 모든 품질 조건이 독립적으로 검증된 것은 아니다. 기계 조립의 시작 장면에는 부품이 이미 놓여 있어 준비 행위나 공구 전수 점검을 촬영한 것으로 설명하지 않는다. IndustReal 원본은 브라우저용 재생본 제작이 필요하다. [공식 자료 및 라이선스](https://github.com/TimSchoonbeek/IndustReal#license).

## 5. 실습 2 계측 판독과 도면 검사 확장

기본 수업은 확보한 장비별 독립 사진·영상으로 판독·단위·확인·교육 기준 비교를 수행한다. 아래 동일 제품 F01~F04 흐름은 목표 확장 기능이며, 현재 원본이 연결되어 있지 않다. 최소 확장 촬영은 제품 하나·디지털 캘리퍼스 하나·검사 위치3곳으로 시작할 수 있다.

### 반드시 구분할 네 단계

1. **제품 식별:** 바코드 → 제품·개체·도면 버전.
2. **검사 위치 식별:** 지금 측정하는 부위 → 도면의 F01~F04.
3. **값 판독:** 장비 표시·주척·버니어 → 원문 값과 단위.
4. **검사 판단:** 위치·장비·절차·단위가 확인된 값 → 해당 기준 비교.

바코드만으로 측정 접촉점이 정해지지 않는다. 기본 팩은 도면에 검사 위치와 표시 좌표를 미리 정의하고, 작업물/치구의 마커·부위 선택·사용자 확인 중 하나로 위치를 연결한다. VLM이 접촉 부위를 보고 위치 후보를 제안하는 기능은 별도 심화로 둔다. 마커가 보인다는 사실만으로 캘리퍼스가 그 부위를 실제 측정했다고 단정하지 않는다.

측정 순서는 `F03 → F01 → F04 → F02`처럼 바꿀 수 있다. ‘다음은 F02’라고 가정하지 않고 현재 확인된 feature ID로 도면에 기록한다. 기본 수업에서 보장하는 무작위성은 **사전에 정의된 여러 부위를 임의 순서로 측정하는 것**이다.

### 예제 도면과 측정 자료

한 개의 간단한 계단형 블록/브래킷을 권장한다. 다음 수치는 자료 설계를 위한 **가상 교육용 값**이며, 실제 촬영·치수·장비 확보 이후 확정해야 한다.

| 위치 | 항목 | 장비 예시 | 교육용 기준 | 계획한 경로 |
|---|---|---|---|---|
| F01 | 외측 폭 | 디지털 캘리퍼스 | 40.00 ± 0.20 mm | 40.02 mm 판독 → 범위 내 |
| F02 | 구멍 내경 | 아날로그 버니어 | 10.00 ± 0.10 mm | 주척·버니어 합산 예제; 눈금이 명확하지 않으면 확인 |
| F03 | 홈 깊이 | 디지털 깊이 게이지 | 8.00 ± 0.20 mm | 8.35 mm → 범위 밖 |
| F04 | 두께 | 마이크로미터 또는 캘리퍼스 | 5.00 ± 0.10 mm | 표시 불명확 → 값·단위·부위 확인 |

기본은 디지털 판독 두 종류, 아날로그 눈금 읽기 한 종류, 불명확 값 확인 한 종류로 구성한다. 네 종류 모두의 완전 자동 인식을 수업 성공의 전제에 두지 않는다. 아날로그 버니어는 눈금 구조를 다루는 문제이며 범용 OCR만으로 해결한다고 설명하지 않는다.

### 화면 진행

`제품 바코드 읽기` → `제품 도면·검사 기준 로드` → `측정 영상 재생` → `측정 위치 후보 확인` → `장비 원본 영역 확대` → `수치·단위 판독` → `기준 비교` → `도면에 기록`을 반복한다.

도면의 F01~F04 위치에 측정값과 상태를 표시하고, 클릭하면 원본 사진·표시 영역·장비·측정 시각·출처가 열린다. 도면 위 표시 좌표는 교재에서 정의한 좌표이며, CAD 도면을 자동 이해해 생성한 좌표처럼 표시하지 않는다.

확인 질문 예: “제품 P-001의 F04 두께가 불명확합니다. F04를 측정한 값과 단위를 알려 주세요.”

응답 `5.04 mm`는 `작업자 확인` 출처로 기록한다. 원래 OCR 문자열과 이미지는 유지한다. 다른 부위나 다른 제품의 답변이면 현재 기록에 적용하지 않는다. 허용 범위에 맞추기 위해 소수점을 임의로 이동하지 않는다. 범위 밖 수치는 실제 불합격 후보와 판독 오류 후보를 구분하여 확인한다.

제품 전체가 합격하려면 필수 위치의 측정이 모두 유효해야 한다. 일부만 범위 안이면 미측정 항목을 표시한다. 이 실습에서는 도면 위치와 측정값의 연결을 명시적으로 확인하므로, 기존 범용 계측 벤치마크와 같은 정확도라고 주장하지 않는다.

### 데이터 준비 판단

기존 계측기 사진은 장비 판독 예제로는 재사용할 수 있지만, 서로 다른 사진을 한 제품의 여러 지점 측정 결과로 묶으면 안 된다. 동일 제품·도면·장비·위치가 연결된 3~4개 측정 클립은 별도 촬영 또는 사용 가능한 동일 제품 자료 확보가 필요하다. 이 부분이 두 번째 실습의 주요 준비 작업이다.

산출물: 측정 기록이 표시된 도면, 치수 검수조서, 품질검사 보고서, 원본 측정 사진, CSV/JSON 기록. 보고서의 자동 판독·작업자 확인·미측정·범위 밖 상태가 모두 구분되어야 한다.

## 6. 확장 실습 부품 키팅과 포장 검사

추가 촬영 후 제공할 확장팩이다. 현재 수업의 세 번째 팩은 확보한 IndustReal 기계 조립·부품 교체 후 재검수로 구성한다. 키팅은 공통 구조를 사용하면서 **종류·수량·구성 완전성·로트 일치**를 다룰 수 있다.

입력은 주문/작업지시 QR, 키트 구성표, 제품 사진, 포장 순서, 트레이 또는 상자 영상이다. 4~6종류의 부품·공구·설명서·케이블을 사용해 탁상에서 촬영할 수 있다.

| 순서 | 수강생 실행 | 시스템 결과 |
|---|---|---|
| 1 | 주문 QR 읽기 | 해당 키트의 BOM·수량·로트·포장 지침 표시 |
| 2 | 부품 배치 장면 확인 | 구성품 존재·수량 후보와 증거 사진 |
| 3 | 빠진 부품 또는 다른 규격 확인 | 누락/불일치 항목을 표시하고 포장 완료 보류 |
| 4 | 가려진 칸 확인 질문에 응답 | 재촬영 자료 또는 확인 답변을 기록 |
| 5 | 라벨과 최종 포장 사진 확인 | 키트·주문·로트의 일치 여부 확인 |
| 6 | 보고서 생성 | 구성품 체크리스트, 포장 검수조서, 출하 검토 보고서 |

학생이 요구 수량을 바꾸거나 다른 라벨을 선택하면 결과가 달라지도록 한다. 상자를 닫은 후의 사진만으로 내부 구성품 수량을 재확인했다고 처리하지 않는다. 포장 전 증거와 봉인/변경 이력을 연결한다.

표시가 있는 트레이와 개별 부품 바코드를 기본으로 하고, 마커 없이 여러 부품을 인식·계수하는 기능은 심화 비교로 둔다. 현재 세 번째 시나리오의 교재 영상은 신규 준비 대상이다.

## 7. 실습 3 재검수와 선택 예시 설비 점검

기본 실습에서는 IndustReal 유지보수 영상으로 긴 차체 부품을 짧은 부품으로 교체하고 재조립하는 흐름을 다룬다. 교체·분리 이후 기존 체결 증거의 효력을 변경하고 새 증거로 재검토한다. 원본 조립 영상과 정비 영상은 개체 동일성이 검증되지 않았으므로 별도 세션으로 둔다. 자세한 단계는 [상세 설계 시나리오 C](MANUFACTURING_WORKSHOP_E2E_BLUEPRINT.ko.md#14-시나리오-c-기계-조립과-재검수)를 따른다.

장비 QR → 일상점검표 → 상태등·압력/온도 표시·필터 상태 확인 → 이상 항목 발견 → 조치 기록 → 새로운 영상으로 재점검 → 점검일지/조치 보고서 생성의 흐름이다.

교육용 탁상 장비나 사전 촬영 자료로 준비한다. 이전 불합격 기록을 지우지 않고 `1차 점검 → 조치 → 2차 점검`을 연결하는 점이 핵심이다. 부품 교환 또는 재작업 이후 과거의 정상 측정값을 재사용하지 않는 것을 보여 준다.

필수 3개 시나리오가 완성된 뒤 준비하는 확장 과제다. 시간이 부족하면 조립 실습의 커버 제거·재장착 경로를 이용해 같은 재점검 원리를 설명할 수 있다.

## 8. 모든 실습에서 생성할 문서

| 출력 | 내용 |
|---|---|
| 검수조서 PDF | 제품/개체/작업지시, 기준 버전, 검사 항목, 기준, 관찰·측정, 판정, 증거, 미확인 항목, 확인자 입력란 |
| 작업 또는 품질 보고서 PDF/HTML | 작업 개요, 시간순 진행, 주요 증거 사진, 질문과 조치, 결과, 남은 항목 |
| 주석 도면 SVG/PNG | F01~F04 위치와 값·단위·상태, 증거 연결 |
| 기록 CSV/JSON | 측정·판정·질문/답변·작업 이력의 구조화된 원본 |
| 증거 묶음 | 참조된 원본/프레임·확대영역, 출처 목록, 실행 설정 |

자동 생성 문서는 초안이다. 실제 확인자가 입력하지 않은 서명·교정 상태·승인을 만들지 않는다. 검수조서와 서술 보고서는 같은 DB 기록에서 생성하여 숫자·판정·사진이 서로 어긋나지 않게 한다.

```text
  instructor/                # 설명·예상 결과·진행 가이드
  tests/                     # 오프라인 전체 흐름과 회귀 확인
  scripts/                   # 자료 준비, 검증, 시작
```

기존 연구 저장소 전체를 공개하지 않고 필요한 코드와 권리 확인된 자산만 선별한다. 교육용 문서·도면·라벨은 직접 작성하고 명시적으로 교육용이라고 표시한다. 데이터의 공개 다운로드 가능 여부와 GitHub 재배포 가능 여부를 구분한다. 코드 라이선스가 데이터 라이선스를 대체하지 않는다.

작은 기본 팩은 저장소 또는 배포 ZIP에 포함하고, 큰 영상은 별도 release 자산/원저작자 다운로드로 제공한다. 거대한 원본 데이터셋이나 모델 가중치 다운로드를 수업 시작 조건으로 두지 않는다. 외부 자료는 원문 라이선스·저작자·링크·변형 사항을 보존한다.

수강생은 사전 준비한 웹 화면 또는 로컬 실행팩으로 시작한다. 개인 모델 API 키와 GPU는 필수로 요구하지 않는다. 브라우저의 마이크 권한·음성 엔진이 없을 때 텍스트 답변과 사전 준비한 음성 안내로 같은 학습 목표를 달성하게 한다. 실시간 ASR을 사용했다면 전사 결과를 먼저 확인하고 해당 질문에 제출한다.

자동화 검증은 설치/자료 확인부터 예제 DB 구축, 각 시나리오, 질문 처리, 보고서 출력까지 CPU 재현 경로를 확인한다. 실제 VLM/OCR 품질 검증은 별도 기록한다. 모델 응답 재현을 실제 인식 성공으로 세지 않는다.

## 10. 4시간 운영표

| 경과 시간 | 분 | 내용 | 수강생 산출물 |

| 02:00–02:10 | 10 | 휴식 | |
| 02:10–03:05 | 55 | 계측 판독·확인 실습 | 원시값·확인값·측정표·검사 보고서 |

소개 35분 + 실습 165분 + 정리 10분 + 휴식 30분 = 240분. 실습은 순수 교육 시간의 약 79%다. 노트북 1인 또는 2인 1대, 같은 준비된 자료를 사용하는 조건으로 설계한다. 개인별 설치 시간이 길면 공용 웹 화면으로 진행하고 로컬 설치는 사후 자료로 제공한다.

소개에서는 모델·도구·DB·규칙·상태·질문을 한 사례로 연결한다. Physical AI는 물리 세계에서 지각과 행동이 연결되는 방향을 설명하고, 이번 교재가 구현하는 범위는 작업 지원·검사·기록이라고 명시한다. 로봇 제어까지 구현한 것으로 소개하지 않는다.

각 팩의 최종 검수는 다음을 포함한다: 정상, 관찰 가능한 불일치, 가림 또는 판독 불가, 확인 이후 해결, 잘못된 제품/부위 답변, 중복 입력, 필수 항목 누락, 재작업 후 이전 증거의 범위, 보고서 값·사진 일치. 정답 기대값은 제어 실습용과 실제 영상 검수용으로 구분한다.
