# 파이프라인 기술 배경과 출력 예시

2026년 11월 23일 · 강사용 보조 원고

모든 출력은 구조 설명을 위한 축약 예시입니다. 실제 API 응답 원문이나 새 모델 실행 결과가 아닙니다. 실습 앱의 수치·조건·판정과 의미를 맞췄으며 기존 원시 기록은 변경하지 않았습니다.

설명 순서: 흐름 확인 → 기술 원리 한 가지 → 출력 필드 읽기 → 이전/이후 상태 비교. 일반 기능 소개보다 이번 버튼 조작으로 어떤 기록이 추가되는지에 초점을 둡니다.

## 13. 실습 준비: 자료와 결과 파일의 구분

**문서를 같은 항목으로 정리** — PDF에서 문장을 꺼내고 CSV의 항목·단위·허용 범위를 확인한 뒤, 같은 제품과 검사 항목으로 연결하는 방식.

- PDF.js: PDF 문자 추출
- CSV: 검사 기준 표
- SQLite: 구조화된 정보 조회

**입력:** 작업지시서 PDF + B 길이 검사 기준 CSV

정보 구축 후의 항목 예시

```text
제품: BSH-2630
항목: B 전체 길이
하한: 39.90
상한: 40.10
단위: mm
```

| 이전 | 이후 |
|---|---|
| 문서와 표에 흩어진 검사 기준 | 제품·항목으로 조회 가능한 기준 |

이 구조를 이후 측정 기록과 판정에서 공통 사용. 자료 다운로드만으로 정보 구축이 완료되지는 않음.

강사 설명: 숫자를 읽을 때마다 문서를 다시 해석하는 대신 기준을 먼저 일정한 구조로 준비하는 원리입니다. 이 표는 뒤에서 정보 구축을 눌렀을 때 얻는 구조를 단순화한 설명용 예시입니다. PDF.js는 PDF 안의 문자를 추출하며, 임의 문서를 의미적으로 완전히 이해하는 도구는 아닙니다. 실습에서는 준비한 CSV와 문서 식별자를 검증하고 SQLite를 구성합니다.

## 23. 실습 준비: 시작 전 점검

**브라우저 안에서 실행** — HTML은 화면, JavaScript는 조작과 판정을 담당. 준비된 관찰을 입력으로 사용하여 GPU 없이 같은 업무 흐름을 실행.

- 정적 웹: 링크로 화면 접속
- 로컬 처리: 입력·규칙 비교
- 브라우저 저장 + JSON 백업

**입력:** 실습 주소 접속 → 전자 조립 선택

시작 전 준비 상태 예시

```text
실습: 전자 조립
입력 자료: PDF + CSV
관찰 입력: 강의용 예시
모델 호출: 0회
검사 기록: 시작 전
```

| 이전 | 이후 |
|---|---|
| 주소와 실습 파일만 확보한 상태 | 자료 화면에서 정보 구축 대기 |

접속과 자료 준비는 작업 완료와 별개. 휴식 후 정보 구축과 작업 시작을 순서대로 실행.

강사 설명: API 키나 별도 GPU 서버를 준비하지 않는 이유를 설명하는 장입니다. 준비된 관찰 예시가 인식 단계의 역할을 대신하지만, 버튼 조작에 따른 기록·판정·보고서 생성은 실제로 실행됩니다. 자료실에서 파일을 내려받은 것과 앱의 DB에 검사 기준을 등록한 것은 서로 다릅니다. 온라인 앱에는 예제 자료가 기본 연결되어 있어 수강생이 모든 파일을 다시 올릴 필요는 없습니다.

## 24. 실습 1(전자 조립): 전체 파이프라인

**관찰 이벤트와 처리 순서** — 이벤트는 새 정보 한 건을 묶은 기록. 대상·검사 항목을 확인해 질문·판정·저장을 연결하는 하네스의 처리 방식.

- 구조화된 출력
- 대상 연결
- 후속 동작

**입력:** 배터리 삽입 장면 99.726초 + E-BATTERY 검사 기준

관찰 이벤트 · 설명용 축약 예시

```text
작업: battery
대상: circuit-board
검사 항목: E-BATTERY
관찰: 배터리 방향 확인 불가
다음 처리: 작업자 확인 질문
```

| 이전 | 이후 |
|---|---|
| 배터리 장면 미확인 | 방향 확인 필요 · 질문 1건 생성 |

관찰 결과를 해당 검사 항목에 연결하고, 부족한 근거는 질문으로 보완하는 흐름입니다.

강사 설명: 모델이 문장을 출력하는 데서 끝나지 않고 작업 ID, 대상, 검사 항목처럼 정해진 칸에 정보를 담아 다음 처리를 연결하는 구조를 설명합니다. 이 예에서는 원본 99.726초 배터리 장면과 E-BATTERY가 연결됩니다. 가려진 방향은 확인 필요로 남기고 작업자 질문을 생성합니다. 이번 실습은 관찰만 미리 작성한 예시이며, 이후 질문·판정·저장은 실제 앱 동작입니다. 표시한 출력은 이해를 위한 축약본으로 실제 API 응답 형식을 보장하지 않습니다.

## 25. 실습 1(전자 조립): 회사 자료의 변환

**문서 추출과 관계형 DB** — PDF 문자 추출 → CSV의 필수 항목·ID 검사 → 작업 ID를 기준으로 연결 → SQLite 표에 저장.

- PDF.js
- CSV 검증
- SQLite

**입력:** SOP의 작업 ID battery + 검사 기준 CSV의 E-BATTERY 행

구축된 검사 기준 · 설명용 축약 예시

```text
{
  "taskId": "battery",
  "criterionId": "E-BATTERY",
  "target": "circuit-board",
  "allowWorker": true
}
```

| 이전 | 이후 |
|---|---|
| PDF 문장과 CSV의 별도 자료 | 작업 battery 조회 → 배터리 방향 기준 호출 |

allowWorker=true는 작업자 확인을 근거로 인정한다는 뜻입니다. 작업 선택 시 같은 기준을 불러옵니다.

강사 설명: PDF.js는 이 실습 PDF에 들어 있는 텍스트를 추출하는 도구이고, CSV는 검사 기준이 이미 행과 열로 정리된 입력입니다. 컴파일러가 회사·공정·작업 ID와 필수 필드를 검증하고 작업과 검사 기준을 SQLite 표로 연결합니다. 예를 들어 battery 작업을 선택하면 E-BATTERY와 대상 circuit-board, 작업자 확인 허용 조건이 함께 조회됩니다. 임의 문서를 모델이 모두 이해해서 온톨로지를 자동 완성했다는 뜻은 아닙니다. 출력의 criterionId는 설명용 이름으로 실제 저장소의 모든 필드를 보여 주는 형식은 아닙니다.

## 31. 실습 1(전자 조립): 관찰과 작업 상태

**진행 상태와 완료 근거의 분리** — 현재 작업은 진행 위치, 검사 결과는 근거의 상태. 동작 시작과 완료 근거를 분리한 상태 관리.

- 상태 관리
- 시각 기록
- 검사 항목별 갱신

**입력:** 89.659초 프로펠러 장착 중 장면 + 이전 작업 기록

장면 관찰 · 설명용 축약 예시

```text
{
  "taskId": "propeller",
  "sourceTime": 89.659,
  "label": "프로펠러 장착 중",
  "assessments": []
}
```

| 이전 | 이후 |
|---|---|
| 회로 연결 완료 · 프로펠러 장면 미확인 | 프로펠러 장착 중 · 완료 근거 미확보 |

빈 assessments는 새 완료 판정이 없다는 뜻입니다. 다음 관찰에서 장착 완료 근거를 별도로 기록합니다.

강사 설명: 89.659초 장면에서는 현재 단계가 프로펠러 장착으로 바뀌지만 체크포인트의 assessments 배열은 비어 있습니다. 따라서 화면을 다음으로 넘겼다는 사실과 프로펠러 완료는 별개입니다. 이어지는 99.726초 관찰에서 E-PROPELLER의 충족 근거를 추가합니다. 이미 열린 배터리 질문도 이후 장면으로 이동했다고 없어지지 않습니다. 실제 현장에서는 영상 인식 결과를 이런 상태 기록에 연결하고, 이번 실습에서는 작성된 관찰을 순서대로 전달합니다.

## 36. 실습 1(전자 조립): 질문과 근거 검증

**작업자 확인과 증거 출처** — 질문·대상·작업 시도에 연결한 답변. 인정 기준을 확인해 판정을 갱신하고 최초 관찰은 별도 보존.

- 질문 상태
- 대상 검증
- 출처 보존

**입력:** 질문 전달 완료 + “방향을 확인했습니다” + 작업자 확인 허용

답변 반영 결과 · 설명용 축약 예시

```text
검사 항목: E-BATTERY
최초 관찰: unknown · 확인 불가
작업자 답변: met · 방향 일치
현재 판정: met · 충족
판정 근거: worker_confirmed
```

| 이전 | 이후 |
|---|---|
| 방향 확인 필요 · 전달된 질문 | 배터리 충족 · 작업자 확인 근거 기록 |

충족의 근거가 영상으로 바뀐 것이 아닙니다. 최초 관찰은 확인 불가로, 추가 답변은 작업자 확인으로 보존합니다.

강사 설명: 질문 확인 버튼으로 전달 상태를 기록한 뒤 해당 대상에 대한 답변을 받습니다. 제어기는 질문과 답변의 대상, 같은 작업 시도인지, 작업자 확인을 허용하는 기준인지 검사합니다. 긍정 답변을 인정하면 현재 판정은 충족이 되지만 rawExampleVerdict의 unknown은 그대로 남습니다. 반대 방향 답변은 불일치가 되고 답변이 없으면 확인 필요가 유지됩니다. 질문 듣기는 음성 출력이고 이번 앱에서 답변은 버튼·텍스트 입력이며 음성 인식은 실행하지 않습니다.

## 44. 실습 1(전자 조립): 기록에서 보고서로

**같은 기록에서 만드는 결과 문서** — 관찰·답변·기준 변경을 모은 검사 원장. 현재 상태를 집계하여 동일 기록에서 보고서와 검수조서 생성.

- 기록 집계
- 문서 틀
- 근거 첨부

**입력:** 6개 장면 완료 + 인정된 배터리 긍정 답변 + 적용 기준

보고서 집계 · 설명용 축약 예시

```text
작업: DEMO-001
검사 항목: 6개
충족 / 불일치 / 확인 필요: 6 / 0 / 0
미해결 질문: 0건
첨부: 장면 사진 · 질문과 답변
```

| 이전 | 이후 |
|---|---|
| 앱 안의 작업 기록과 검사 결과 | 동일 기록의 보고서 HTML · 검수조서 생성 |

보고서 생성은 기존 판정의 문서화입니다. 미답변이면 충족 5개·확인 필요 1개가 그대로 출력됩니다.

강사 설명: 보고서 단계에서 모델에게 새 합격 판정을 맡기는 대신 이미 저장된 기록과 현재 검사 결과를 모읍니다. 정상 비교 경로는 6개 장면을 모두 기록하고 배터리 긍정 답변을 인정했을 때 충족 6개, 열린 질문 0건입니다. 미답변 상태로 보고서를 만들면 확인 필요 1개가 그대로 남습니다. 보고서에는 사진·원본 시각·질문·답변·적용 정책을 함께 제시해 결과를 설명할 수 있도록 합니다. 강의용 기준 충족은 실제 물리적 검사 승인이나 전기 성능 인증이 아닙니다.

## 51. 실습 1(전자 조립): 판정 조건의 비교

**입력 보존과 규칙 재계산** — 같은 원기록에 새 인정 기준을 적용한 재계산. 기존 답변을 보존하고 기준 변경과 새 판정을 함께 기록.

- 조건 분리
- 규칙 기반 판정
- 변경 이력

**입력:** 완료된 6개 장면 + 긍정 답변 유지 + 시각 증거만 인정으로 변경

동일 입력의 조건 비교 · 설명용 축약 예시

```text
원래 관찰: 방향 확인 불가
작업자 답변: 방향 일치 · 그대로 보존
기준: 작업자 확인 인정 → 시각 증거만
배터리: 충족 → 확인 필요
전체: 충족 6 → 충족 5 + 확인 필요 1
```

| 이전 | 이후 |
|---|---|
| 작업자 확인 인정 · 충족 6개 | 시각 증거만 인정 · 충족 5개 + 확인 필요 1개 |

답변 자체는 남지만 현재 기준이 인정하지 않는 근거입니다. 반대 답변 비교 전에는 인정 기준을 먼저 복구합니다.

강사 설명: 정책 비교에서는 영상과 작업자 답변을 그대로 두고 allowWorker만 바꿉니다. 시각 증거만 인정하면 같은 긍정 답변이 저장되어 있어도 배터리는 확인 필요가 되고 전체 충족 수는 6개에서 5개가 됩니다. 그다음 작업자 확인 인정 기준을 복구하고 새 확인 질문에 반대로 들어가 있다고 답하면 충족 5개와 불일치 1개가 됩니다. 두 조건을 동시에 바꾸지 않아야 차이의 원인을 설명하기 쉽습니다. 변경 전후 기준과 과거 답변은 기록으로 남습니다.

## 63. 실습 2(계측 검사): 전체 파이프라인

**인식 결과와 검사 규칙의 분리** — 문자 인식(OCR)은 읽은 값을 제안하고, 제어기는 선택한 제품의 기준과 비교하여 검사 상태를 갱신하는 구조.

- 문자 인식(OCR)
- 기준 조회
- 상태 갱신

**입력:** 표준형 제품 선택 + A/B/C 계측 장면 + 검사 기준

중간 기록 예시 · 설명용 간략 형식

```text
제품: BSH-2630 / 도면 개정: A
A 외경: 26.30 mm → 충족
B 길이: 40.02 mm → 충족
C 두께: 원문 5.?8 mm / 확정값 없음
검사 상태: 충족 2 / 확인 필요 1
```

| 이전 | 이후 |
|---|---|
| 검사 시작 · A/B/C 모두 미기록 | A/B 기록 완료 · C는 질문 대상으로 전환 |

한 항목의 판독이 불명확해도 다른 항목은 기록하고, C의 확인 요청만 별도로 유지.

강사 설명: 현장형 구성에서는 OCR이 계측기 화면에서 문자 후보를 만들고, 영상 분석은 검사 위치와 대상을 제안합니다. 이 제안은 검사 기준과 대조되는 입력이며 그 자체가 합격 승인과 같지는 않습니다. 이번 실습에서는 판독 후보와 위치를 준비된 예시로 제공하고 제품 기준 조회·수치 비교·기록 갱신을 실제 코드로 처리합니다. 화면의 다섯 줄은 이 중간 기록을 이해하기 위한 간략 표현으로 실제 API 응답 원문이 아닙니다.

## 70. 실습 2(계측 검사): 판독값과 도면 위치의 연결

**제품·도면·검사 위치의 연결 키** — DB의 연결 키는 서로 다른 표의 같은 대상을 가리키는 식별자. 숫자에 제품·시료·도면·위치를 붙여 기록하는 방식.

- 대상 식별자
- 도면 위치 연결
- 근거 이미지

**입력:** 표준형 A 외경 장면 + 원문 26.30 mm + A 허용 범위

측정 레코드 예시 · 설명용 간략 형식

```text
제품: BSH-2630 / 시료: EDU-BSH-001
도면: DR-BSH-2630 / 개정: A
검사 위치: A · 플랜지 외경
원문: 26.30 mm / 기록값: 26.30
단위: mm / 근거: A 장면
적용 기준: 26.10–26.50 mm → 충족
```

| 이전 | 이후 |
|---|---|
| A 장면 선택 · 아직 검사표에 값 없음 | A에 26.30 mm 기록 · 도면·근거와 함께 표시 |

측정값 기록 버튼으로 동일 제품의 A 기준에 연결. 장면 미리보기만으로는 검사 기록 변화 없음.

강사 설명: 같은26.30이라는 숫자라도 어느 제품의 어느 면을 측정했는지 없으면 검사표에 넣기 어렵습니다. 그래서 품번, 실제 검사 시료, 도면 개정, 위치 식별자를 한 기록에 연결합니다. 실습의 A/B/C 위치는 미리 정의한 연결이며 실제 영상에서 자동 위치 인식을 수행한 결과는 아닙니다. 여기서는 A 장면을 보는 동작과 측정값을 확정 기록하는 버튼 동작의 차이를 함께 설명합니다.

## 76. 실습 2(계측 검사): 불확실한 값의 확인

**미확정 값과 작업자 확인값의 분리** — 질문에 검사 대상과 항목을 연결하고, 전달된 질문의 답변만 검증·추가하는 방식. 최초 판독 문자열은 그대로 보존.

- 질문 상태
- 값·단위 검사
- 출처 보존

**입력:** C 원문 5.?8 mm + 질문 전달 + 작업자 답변 5.78 mm

확인 후 기록 예시 · 설명용 간략 형식

```text
검사 위치: C · 플랜지 두께
최초 원문: 5.?8 mm
확인값: 5.78 mm / 출처: 작업자
답변 연결: 전달된 C 질문
기준: 5.70–5.90 mm → 충족
질문 상태: 해결
```

| 이전 | 이후 |
|---|---|
| C 확인 필요 · 원문만 보존 · 질문 대기 | C 충족 · 작업자 확인값 추가 · 질문 해결 |

질문·대상·단위와 값 형식을 확인한 뒤 범위 비교. 578 mm는 그대로 범위 밖이며 5.78로 자동 수정하지 않음.

강사 설명: 먼저 C 질문을 전달하고 값과 단위를 입력한 뒤 확인값 기록 버튼을 눌러야 새 답변이 저장됩니다. 입력란에 숫자를 타이핑한 것만으로는 검사 결과가 바뀌지 않습니다. 확인된5.78mm는 작업자 출처의 새로운 정보이며 원문5.?8mm를 덮어쓰지 않습니다. 이후 같은 표준형 기준5.70–5.90mm로 비교하므로 C가 충족으로 바뀌고 질문이 해결됩니다.578mm를 입력했다면 소수점을 추측하지 않고 불일치로 기록합니다.

## 80. 실습 2(계측 검사): 검수조서의 구성

**같은 검사 기록에서 문서 생성** — 검사표·질문·근거를 항목별로 묶어 문서 양식에 채우는 방식. 새 판독이나 새로운 합격 판단 없이 현재 기록을 출력.

- 기록 집계
- 문서 양식
- 근거 연결

**입력:** 표준형 A/B 기록 + C 5.78 mm 확인 + 현재 적용 기준

검수조서 데이터 예시 · 설명용 간략 형식

```text
제품: BSH-2630 / 도면: DR-BSH-2630 A
A 외경: 26.30 mm / 충족
B 길이: 40.02 mm / 충족
C 두께: 5.78 mm / 충족 / 작업자 확인
종합: 충족 3 / 확인 필요 0
첨부: 도면·장면·질문/답변 이력
```

| 이전 | 이후 |
|---|---|
| 값·질문·근거가 검사 화면에 누적 | 같은 내용을 HTML 검수조서·검사 CSV로 저장 |

보고서 버튼은 기록을 새 형식으로 출력하는 동작. 미답변 항목이 있으면 그 상태도 보고서에 유지.

강사 설명: 이 예시는 표준형의 세 위치를 기록하고 C를5.78mm로 확인한 기본 조건입니다. 앱은 현재 검사 상태를 표와 문서 양식으로 바꾸며 보고서 작성 과정에서 측정값이나 미해결 항목을 새로 만들어 내지 않습니다. C가 미답변이면 확인 필요가 남는 보고서가 생성됩니다. 도면 기준과 실습 중 수정한 기준, 장면과 답변의 출처를 함께 확인하고 교실 예시가 실제 검사 승인이나 계측 인증은 아니라는 점을 설명합니다.

## 87. 실습 2(계측 검사): 기준과 확인값의 비교

**판독과 분리된 범위 비교** — 측정값·단위·상하한을 따로 저장하고 소수 자릿수를 맞춰 비교. 기준이 바뀌면 같은 값을 새 범위로 다시 계산.

- 소수 비교
- 기준 변경 이력
- 재판정

**입력:** B 40.02 mm 유지 + 상한 변경 / 이후 C 확인값 변경

조건별 판정 예시 · 설명용 간략 형식

```text
B 기록값: 40.02 mm / 변경 없음
원래 기준: 39.90–40.10 → 충족
상한 변경: 39.90–40.01 → 불일치
상한 복원: 39.90–40.10 → 충족
C 확인값: 5.78 → 578 mm
C 결과: 충족 → 불일치 / 입력값 유지
```

| 이전 | 이후 |
|---|---|
| 표준형 기본 조건 · B와 C 모두 충족 | 변경한 조건에 따라 해당 항목만 재판정 |

B는 기준 변경 효과를 비교한 뒤 복구. 이어 C 답변을 바꾸어 값 변경 효과를 따로 확인.

강사 설명: B의40.02mm는 그대로 두고 상한만40.10에서40.01로 바꾸면 불일치가 됩니다. 이는 숫자 인식 실패가 아니라 적용 기준이 달라진 결과입니다. 다음 비교 전에 상한40.10을 복구하여 두 실험의 영향을 분리합니다. 이어 C의 확인값을578mm로 바꾸면 표준형 범위5.70–5.90mm를 벗어나며 앱은 이를5.78로 고치지 않습니다. 여기의 B 하한39.90은 유지되므로 정밀형 제품 기준39.99–40.01과 혼동하지 않도록 합니다.

## 97. 실습 2(계측 검사): 제품 변경과 기준 재호출

**제품별 기준과 검사 세션의 분리** — 품번으로 기준 묶음을 조회하고 새 검사 세션을 생성. 세션은 한 제품 검사에 속한 값·질문·근거를 모으는 단위.

- 제품별 조회
- 새 검사 세션
- 기록 분리

**입력:** BSH-2630-P 정밀형 선택 + 새 정보 구축·검사 시작

새 검사 시작 예시 · 설명용 간략 형식

```text
제품: BSH-2630-P / 새 검사 기록
도면: DR-BSH-2630-P / 개정: A
검사 시료: EDU-BSH-P-001
B 기준: 39.99–40.01 mm
기존 측정값 자동 복사: 없음
A/B/C 현재 기록: 모두 미기록
```

| 이전 | 이후 |
|---|---|
| 표준형 검사: 값·질문·결과 보유 | 정밀형 기준 호출 · 빈 검사 기록 |

다시 기록한 값: A·C 충족, B 40.02 mm 불일치. 제품만 바꾸면 이전 값이 자동 복사되지는 않음.

강사 설명: 제품 선택만 바꾸는 것이 아니라 그 제품의 문서와 기준을 구축한 다음 새 검사 기록을 시작합니다. 그래서 정밀형으로 옮겼을 때 이전 표준형의 수치와 작업자 답변이 그대로 따라오지 않습니다. 이후 A26.30mm, B40.02mm와 C5.78mm를 다시 입력하는 동일 비교 조건에서는 정밀형의 좁은 B 기준 때문에 충족2개와 불일치1개가 됩니다. 제품별 도면 ID와 검사 시료를 별도로 연결하며 두 도면의 현재 개정은 A입니다. 화면의 출력 예시는 새 검사 시작 시점을 나타냅니다.

## 115. 결과 정리: 보고서·데이터·진행 상태

**같은 기록의 여러 표현** — 누적 기록을 HTML·CSV·DB로 변환하고, 진행 JSON에는 기준과 답변을 함께 보관해 이전 상태를 복원하는 방식.

- HTML: 사람에게 보여주는 결과
- CSV·DB: 표와 구조화된 기록
- JSON: 상태를 다시 읽는 파일

**입력:** 직전 정밀형 검사: A·C 충족, B 불일치

저장·복원할 정보 예시

```text
제품: BSH-2630-P
검사 항목: A / B / C
충족: 2 · 불일치: 1
C 확인값: 5.78 mm
미해결 질문: 0
```

| 이전 | 이후 |
|---|---|
| 현재 브라우저에 남아 있는 검사 | JSON 가져오기 후 동일 검사 복원 |

보고서는 결과 열람용, 진행 JSON은 복원용. 파일을 바꾸어 불일치를 지우는 과정이 아님.

강사 설명: 같은 기록을 여러 형식으로 표현하는 것이므로 보고서와 CSV에서 값이 서로 다르면 안 됩니다. 여기서는 정밀형에서 나온 B 길이 불일치를 포함해 저장하고 복원합니다. HTML 보고서를 열어 보는 동작과 진행 JSON을 앱으로 가져오는 동작은 구분합니다. 복원 후에는 제품, 적용 기준, 확인값과 질문 이력을 함께 확인합니다.

## 121. 실습 결과: 솔루션 적용과 비교 정리

**조건 하나만 바꾸는 비교** — 관찰값을 고정하고 기준이나 답변 하나만 바꾸어, 어떤 정보가 판정에 영향을 주었는지 확인하는 방식.

- 입력값 고정
- 변경 조건 명시
- 전후 판정·근거 대조

**입력:** B 기록값 40.02 mm 유지, 상한만 변경

조건별 판정 비교 예시

```text
기록값: 40.02 mm
기본 범위: 39.90–40.10
기본 판정: 충족
변경 범위: 39.90–40.01
변경 판정: 불일치
```

| 이전 | 이후 |
|---|---|
| 기본 기준에서 B 항목 충족 | 좁힌 기준에서 B 항목 불일치 |

변경한 기준과 같은 측정값을 함께 기록. 결과 변화는 규칙 적용의 사례이며 모델 정확도 점수가 아님.

강사 설명: 같은 숫자라도 적용 기준에 따라 판정이 달라진다는 점을 정리합니다. 합격을 많이 만드는 것이 목적이 아니라 어떤 근거와 규칙이 결과를 바꾸었는지 설명할 수 있어야 합니다. 현장 적용에서는 기준의 승인·개정 관리가 추가로 필요하며 수강생의 실습 변경이 회사 기준 승인을 뜻하지 않습니다. 제출할 때는 기본 결과, 변경 조건, 변경 후 결과를 함께 남기도록 안내합니다.
