슬라이드 제목은 일반적인 주제형 표기, 화면 본문은 명사형 불릿입니다. 아래 메모는 강사가 말로 전달할 문장이므로 서술형입니다.

## 설명 범위

도입부의 전체 구조는 솔루션의 목표 업무 흐름입니다. 실제 현장의 모든 조건에서 검증된 인식 성능이나 자동 승인을 주장하지 않습니다. 교실 앱은 강의용 관찰 예시와 가상 계측 장면을 사용합니다. PDF 텍스트 추출, CSV 검증, SQLite 구성, 작업자 답변, 허용 범위 비교, 보고서 생성은 실제 브라우저 기능입니다. 로봇·설비 제어, 실시간 스마트 글래스·OCR·음성 인식은 이번 실습에 포함되지 않습니다.

### 01. 제조 AI Agent: DyninAI 솔루션 소개

설명 1분

0–30초: 오늘은 회사의 작업 기준과 현장의 관찰을 연결하는 제조 AI Agent를 소개합니다. 전자 조립과 치수 검사 두 가지 예시로, 무엇을 보고 무엇을 물으며 어떤 근거를 남기는지 확인할 예정이라고 안내합니다.
30–60초: 첫 25분은 배경과 DyninAI 구조 설명, 다음 25분은 접속·파일 다운로드·실습 준비입니다. 이후 10분 휴식과 전자 조립 실습이 이어집니다. 지금은 강사 화면을 보고, 접속 시작을 안내한 뒤 함께 조작하도록 요청합니다.

### 02. 제조 현장: 기준·작업·기록의 연결

설명 2분

0–1분: 수강생이 앞선 교육에서 만든 품질 검사 화면과 검사 이력을 떠올리게 합니다. 예를 들어 작업자는 도면을 찾고, 치수를 재고, 표에 쓰고, 사진을 다시 첨부합니다. 각각의 도구가 있어도 같은 제품·같은 작업의 정보로 연결하는 일이 남아 있습니다.
1–2분: AI 도입의 목적을 단순한 문서 요약보다 기준과 현장 기록의 연결로 설명합니다. 현장에서 자료를 다시 찾거나 수기로 옮겨 적는 단계가 어디인지 한 가지 짧게 물어봅니다. 회사 소개자료의 비용·기간 수치는 검증된 일반 통계로 제시하지 않습니다.
참고: R3:2–4; R6:2–3. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 03. AI Agent: 정보 조회와 후속 처리

설명 2분

0–1분: 흐릿한 숫자 사진을 설명하는 답변만으로 검사가 끝나지 않는다는 예를 듭니다. 어떤 제품의 어느 치수인지 조회하고, 값을 확정할 수 없으면 질문하고, 답변을 받은 뒤 기준과 비교하는 연속 처리가 필요합니다. 이를 수행하는 업무 단위를 Agent로 소개합니다.
1–2분: 모델은 관찰 내용을 해석하고, 프로그램은 자료 조회와 비교·저장을 실행합니다. 모든 단계를 LLM으로 처리할 필요는 없습니다. 앞선 질문이 해결되지 않은 상태를 유지하는 기능도 Agent 시스템의 일부입니다.
참고: R6:12–14; R7:13. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 04. DyninAI: 제조 AI 플랫폼 구성

설명 3분

0–1분: DyninAI는 전체 플랫폼 이름이고 Dynin-Omni는 그 안에서 문서·이미지·영상·음성을 다루는 모델이라고 구분합니다. 회사 소개자료에는 Dynin-Omni, Field Ontology, Dynin-Robotics가 공통 현장 정보를 활용하는 구성으로 제시되어 있습니다.
1–2분: 온톨로지에는 제품, 부품, 공구, 작업 순서와 검사 기준의 관계가 들어갑니다. 업무 Agent는 이 정보를 꺼내 관찰 결과와 연결하고, 질문이나 기록 도구를 실행합니다. 이 슬라이드는 제공 자료를 바탕으로 수업 목적에 맞게 재구성한 개념도이며 실제 배포 서버 구성을 그대로 그린 것은 아닙니다.
2–3분: Physical AI는 물리 환경의 상태와 행동을 다루는 영역으로 소개합니다. Dynin-Robotics는 작업 이해와 상태 예측, 로봇 제어를 다루는 확장 축입니다. 오늘은 작업자를 지원하는 문서·영상·계측 흐름을 체험하며, 실제 로봇이나 설비는 제어하지 않습니다.
참고: R1:5,10–12; R3:3–5,13–14; R7:13. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 05. Dynin-Omni: 문서·영상·음성의 통합

설명 2분

0–1분: 옴니모달은 입력 형식이 서로 달라도 함께 다룬다는 뜻으로 풉니다. SOP 문장, 손과 부품이 보이는 영상, 작업자가 말한 확인값을 같은 작업의 맥락으로 연결하는 예를 듭니다. 이해와 생성은 각각 입력 해석과 결과 표현을 뜻합니다.
1–2분: 소개자료에서는 Dynin-Omni를 단일 백본과 Masked Diffusion 기반의 통합 모델로 설명합니다. 기술 질문이 나오면 가려진 토큰을 문맥으로 반복 복원하는 방식이라고 짧게 풉니다. 이 방식만으로 모든 현장 업무에서 더 빠르거나 정확하다고 단정하지 않습니다. 오늘 앱은 이 모델을 실시간 실행하지 않고 준비된 관찰 예시를 사용합니다.
참고: R1:6–9; R3:6–9; R4:3–5,7; R5:2–4. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 06. 현장 온톨로지: 제품·작업·기준의 관계

설명 2분

0–1분: 온톨로지를 현장에 있는 대상과 관계를 정리한 정보 구조로 설명합니다. 표의 숫자 40.02만 저장하면 어느 제품의 어느 치수인지 알 수 없습니다. BSH-2630 제품, B 전체 길이, mm 단위, 적용 도면과 허용 범위를 함께 연결해야 합니다. 그림의 제품과 값은 강의를 위한 가상 예시입니다.
1–2분: 실제 현장에서는 문서와 도면의 검토를 거쳐 기준을 확정합니다. 이번 앱에서는 준비된 SOP PDF와 검사 기준 CSV를 읽어 SQLite 표로 구성합니다. 완성된 범용 온톨로지를 자동 생성하는 실습은 아니며, 제품을 선택하면 연결된 기준을 일관되게 불러오는 원리를 체험합니다.
참고: R3:3–5; R6:4–7,9; R7:3,5. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 07. 제조 Agent: 사전 설정과 현장 실행

설명 3분

0–1분: 관리자 준비와 작업자 실행을 나누어 설명합니다. 관리자는 SOP, 도면, 검사 기준과 적용 버전을 등록하고 확인합니다. 작업자는 자신이 수행할 제품과 공정을 선택합니다. 기준이 확정되면 매번 문서를 새로 해석하지 않고 필요한 정보를 불러올 수 있습니다.
1–2분: 이후 영상에서 진행을 관찰하고, 가려진 장면이나 불명확한 숫자는 질문으로 연결합니다. 질문에 답했는지와 해당 답변을 어떤 기준에서 인정하는지까지 함께 확인합니다. 실제 현장의 스마트 글래스 입력은 이번 강의에서 영상·장면 사진으로 대체합니다.
2–3분: 확인된 결과는 중간 기록에 누적합니다. 다음 장면으로 넘어가도 앞 작업의 미해결 항목은 남습니다. 마지막 보고서에는 작업 중 쌓인 기준, 사진, 측정값, 질문과 답변이 들어갑니다. 현장용 시스템은 권한·연결·승인 절차를 추가로 갖춰야 합니다.
참고: R2:2; R6:3–19; R7:4,6–7,11–13. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 08. 판정과 검토: 모델·시스템·사람의 역할

설명 2분

0–1분: 영상에 체결 동작이 보여도 실제 토크는 영상만으로 확정할 수 없다는 예를 듭니다. 보이는 동작, 장비나 센서가 제공한 수치, 작업자의 확인은 서로 다른 종류의 근거입니다. 확인할 수 없는 항목을 자동 합격으로 바꾸지 않습니다.
1–2분: 원자료는 충족·위반·판단 유보·관찰 불가를 구분합니다. 수업 앱은 충족·불일치·확인 필요의 세 결과를 보여 주고, 정보 부족의 이유를 기록합니다. 작업자 답변은 출처가 있는 추가 증거이며 최종 품질 승인과 같지 않습니다. 기준 변경도 원기록을 지우지 않고 새 판정을 만드는 과정입니다.
참고: R5:10; R6:7,13,15,17; R7:9–10,13. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 09. 제조 적용 사례: 조립·검사·정비·점검

설명 2분

0–1분: 회사 Use-case 자료에서 네 가지 적용 유형을 골라 소개합니다. 조립은 해야 할 동작과 실제 장면의 대조, 검사는 도면과 값의 대조, 정비는 증상과 점검 절차의 연결, 순회 점검은 현장 사진과 기록의 연결입니다. 원자료에는 개념·가상 예시도 포함되어 있으므로 모두 실제 고객 적용 실적처럼 설명하지 않습니다.
1–2분: 서로 다른 분야에서도 대상 선택, 관련 기준 조회, 확인, 기록이라는 공통 흐름을 찾을 수 있습니다. 오늘은 앞의 두 가지를 직접 조작하며 정비와 순회 점검은 적용 가능성을 이해하는 사례로 소개합니다. 수강생에게 자기 업무가 어느 유형에 가까운지 잠깐 생각하도록 안내합니다.
참고: R1:16–31; R2:3–10; R5:5. 자료 번호와 원본 페이지는 slides/REFERENCES.ko.md 참조.

### 10. 적용 사례(전자 조립): 작업 확인

### 22. 실습 1(전자 조립): 질문과 답변

설명 2분

### 23. 실습 1(전자 조립): 판정 조건 비교

### 24. 실습 1(전자 조립): 보고서 저장

### 26. 실습 2(계측 검사): 제품 선택

설명 1분

상단 ‘진행 내보내기’로 전자 실습 JSON을 저장한 뒤 좌측 ‘실습 선택’으로 이동합니다. 계측 카드의 ‘이 실습 시작’을 누르고 기존 진행을 새 실습으로 바꾼다는 알림을 확인합니다. 계측 제품 도해와 장비 표시는 같은 가상 제품을 설명하기 위해 만든 강의용 예시입니다. 실제 기업 제품이나 실제 OCR 결과로 소개하지 않습니다. 표준형으로 모두 시작한 뒤 뒤에서 정밀형을 비교합니다.

### 27. 실습 2(계측 검사): 검사 대상 확인

설명 1.5분

도면의 A, B, C 위치를 차례로 가리킵니다. ‘26.30’이라는 숫자만 있으면 어느 제품의 어떤 치수인지 알 수 없다고 설명합니다. 제품번호는 제품 종류, 시편은 이번 검사 대상 한 개, 개정은 적용한 도면 버전입니다. 선택은 사용자가 한 것이며 영상에서 제품을 자동 식별한 결과가 아닙니다. A/B/C도 미리 정의한 도면 위치입니다. 수강생이 짝에게 네 가지 연결을 말하게 합니다.

### 28. 실습 2(계측 검사): 검사 기준 등록

설명 1.5분

제품 아래 자료 구역에서 ‘검사 기준 불러오기 · 정보 구축’을 누릅니다. 실제 SOP PDF 추출과 CSV 검증으로 제품·도면·기준을 구성하는 점은 전자 실습과 같습니다. ‘검사 시작 준비’를 누르면 도면과 장비 순서를 한 번 더 볼 수 있습니다. 모두 mm 단위인지 확인하고 ‘측정 기록 시작’을 누릅니다. 허용 범위는 이 수업의 도면에 정해진 범위이며 임의 공장의 규정이나 장비 정확도를 뜻하지 않습니다.

### 29. 실습 2(계측 검사): 측정값 기록

설명 1.5분

A를 기록한 뒤 바로 B로 넘어가지 말고 도면의 A와 측정표의 A 행을 함께 보여 줍니다. B도 같은 방식입니다. 앱에서는 준비한 장면 후보를 기록 버튼으로 채택하며 실제 장비에서 실시간 수치가 들어오는 기능이 아닙니다. 작은 A/B/C 버튼을 눌러 사진을 미리 보는 것과 ‘측정값 기록’ 버튼을 누르는 것은 다릅니다. 수강생에게 40.02가 왜 표준형 범위 안인지 숫자로 설명하게 합니다.

### 30. 실습 2(계측 검사): 측정값 확인

설명 2분

C 장면은 플랜지 가장자리의 두께를 보여 주는 부분 확대 도해입니다. C를 기록하고 먼저 확정 숫자가 없다는 점을 보여 줍니다. 질문 확인을 누른 뒤 수강생이 5.78과 mm를 직접 입력합니다. ‘예시값 5.78 mm 넣기’ 버튼은 입력란을 채울 뿐이므로 ‘확인값 기록’을 별도로 눌러야 합니다. 메모에는 ‘강의의 작업자 역할 답변’이라고 적게 해도 좋습니다. 이 값은 실제 장비를 읽어 검증한 값이 아니라 수업에서 제출한 값입니다. 답변 전에는 충족 2 + 확인 필요 1, 답변 후에는 충족 3입니다.

### 31. 실습 2(계측 검사): 확인 이력 관리

설명 1.5분

‘전체 검사 결과’ 또는 마지막 장면의 ‘검수조서 만들기’로 결과 화면에 갑니다. 측정표의 최초 후보와 작업자 확인 기록을 나란히 읽습니다. ‘C 확인값 다시 입력’을 누르면 예전 답변은 이력에 남지만 현재 확인은 다시 대기합니다. ‘질문 확인’을 다시 눌러야 새 답변을 제출할 수 있습니다. 6.08 또는 578과 mm를 제출하면 임의 소수점 보정 없이 불일치가 됩니다. inch는 mm를 요구하는 이 예시의 단위와 달라 거부됩니다. 비교 전에 기본 5.78 결과를 내보내 두고, 시연 후 5.78로 재확인하여 다음 활동의 조건을 맞춥니다.

### 32. 실습 2(계측 검사): 허용 범위 변경

설명 2분

‘허용 범위를 바꾸어 비교’에서 B 전체 길이 폼만 수정합니다. 하한 39.90은 유지하고 상한만 40.01로 바꿉니다. 범위는 하한과 상한을 포함하여 비교합니다. 40.02가 40.01보다 0.01 크므로 불일치입니다. 화면에 원본 도면 기준과 실습 적용 기준이 함께 표시되는지 확인합니다. 이것은 수업의 조건 비교이며 도면 개정이나 생산 기준 승인을 실행하는 기능은 아닙니다. 비교 파일을 저장한 뒤 40.10으로 되돌립니다.

### 33. 실습 2(계측 검사): 제품별 기준 비교

설명 1.5분

표준형 결과와 진행 JSON을 먼저 저장합니다. ‘다른 제품 선택’은 제품·도면 화면으로 이동하는 버튼입니다. 여기서 BSH-2630-P의 ‘정밀형 플랜지 부시’를 눌러 새 제품을 선택하고 기존 최근 세션을 바꾸는 알림을 확인합니다. 두 제품 모두 개정 A지만 제품·도면·시편 ID가 다릅니다. 표준형 측정값을 자동으로 이어 쓰지 않으며 ‘검사 기준 불러오기 · 정보 구축’부터 다시 시작합니다. 새 장면에 같은 예시 숫자가 준비되어 있으나 새로운 기록입니다. 5.78 답변까지 제출하면 길이 B만 범위 밖입니다. 비교표의 범위 단위는 모두 mm입니다.

### 34. 실습 2(계측 검사): 검수조서 저장

설명 1분

측정 화면의 마지막 ‘검수조서 만들기’는 먼저 검사 결과로 이동하고, 결과 화면에서 같은 이름의 버튼을 한 번 더 누르면 저장 화면입니다. ‘검수조서 저장’으로 단독 HTML을 받습니다. 결과 보고서는 ‘도면 포함 HTML 저장’, 표는 ‘검사 CSV’, PDF는 ‘인쇄 / PDF 저장’을 사용합니다. 서명과 실제 검사일을 자동 승인 사실처럼 채우지 않습니다. 정밀형의 불일치가 보고서에서도 유지되는지 확인합니다. 표준형과 정밀형을 파일명으로 구분합니다.

### 35. 결과 저장과 진행 복구

설명 1분

현재 실습을 ‘진행 내보내기’로 저장하고 브라우저를 새로고침합니다. 같은 주소·브라우저에서는 저장 상태가 복구됩니다. 다른 주소나 PC에서는 JSON을 ‘가져오기’로 불러옵니다. 보고서 HTML은 실습 앱의 백업 파일이 아니므로 가져오기에 넣지 않습니다. 보고서의 ‘실행 JSON’도 진행 백업에 사용할 수 있습니다. 새 제품을 고르기 전 백업하는 습관을 강조합니다. SQLite 파일은 구축한 표와 기록을 확인하는 추가 산출물로 소개하되, SQL을 다루는 활동은 필수가 아닙니다.

### 36. 현장 업무 적용 검토

설명 2분

2인 또는 소그룹으로 진행합니다. 실제 회사 자료를 앱에 업로드하지 않고 작업 이름과 필요한 정보 종류만 활동지에 적습니다. 답변 예: ‘부시 외경 검사 / 도면 개정과 외경 범위 / 제품·시편·A 위치 / 표시가 가려지면 값과 단위 재확인 / 최초 표시와 확인값·판정 보관’. 조별로 한 작업을 선택하고 자료→대상→질문→판정→기록을 5칸에 적습니다. 발표 때는 자동화 효과를 수치로 추정하기보다 누가 기준을 확인하고 미확인 항목을 처리할지 설명하게 합니다.

### 37. 실습 결과 정리 및 제출

설명 1분

수강생에게 ‘장면이 끝났는데 확인이 남을 수 있는가’, ‘5.?8을 왜 그대로 남기는가’, ‘40.02가 제품에 따라 왜 다른 판정인가’를 묻습니다. 기대 답은 각각 ‘미답변·미검토가 남기 때문’, ‘원기록과 확인 근거를 구분하기 위해’, ‘적용하는 허용 범위가 다르기 때문’입니다. 제출 폴더에서 전자 기본·변경 보고서, 표준형·정밀형 검수조서, JSON, 이유 문장과 업무 흐름을 확인합니다. 모든 산출물은 강의용 예시이며 오늘의 결과를 실제 제품 승인이나 AI 성능 지표로 해석하지 않습니다.
