## 설명 범위

도입부의 전체 구조는 솔루션의 목표 업무 흐름입니다. 실제 현장의 모든 조건에서 검증된 인식 성능이나 자동 승인을 주장하지 않습니다. 교실 앱은 강의용 관찰 예시와 가상 계측 장면을 사용합니다. PDF 텍스트 추출, CSV 검증, SQLite 구성, 작업자 답변, 허용 범위 비교, 보고서 생성은 실제 브라우저 기능입니다. 로봇·설비 제어, 실시간 스마트 글래스·OCR·음성 인식은 이번 실습에 포함되지 않습니다.

## 슬라이드별 진행 메모

### 01. 제조 AI Agent: 솔루션 소개

설명 2분

0–1분: 오늘은 제조 업무를 대신 설명하는 챗봇보다, 작업에 필요한 자료와 현장 기록을 연결하는 방식을 살펴본다고 소개합니다. 전자 조립 장면과 계측 도해를 각각 가리킵니다.
1–2분: 첫 25분은 배경과 솔루션 소개, 다음 25분은 각자 링크에 접속하고 파일을 준비하는 시간이라고 알립니다. 10분 휴식 후 본 실습을 시작합니다. 처음부터 버튼을 따라 누를 필요는 없으며, 접속 활동 시작을 별도로 안내합니다.

### 02. 제조 업무: 자료와 기록의 연결

설명 3분

0–1분: 부품 하나를 검사하는 상황을 제시합니다. 작업자는 도면을 찾고, 개정을 확인하고, 측정하고, 검사표에 값을 옮겨 적습니다. 이 과정이 분리되어 있으면 나중에 숫자만 남고 어떤 대상의 어떤 기준을 썼는지 다시 찾아야 할 수 있습니다.
1–2분: 조립에서도 같은 문제가 있습니다. 작업은 끝났지만 가려진 체결부의 확인 사진이나 작업자 답변이 빠질 수 있습니다. 이런 상황에서 필요한 것은 단순 합격 표시보다 미확인 항목을 찾아 남기는 기능입니다.
2–3분: 수강생에게 실제 업무에서 자료 찾기·재확인·기록 중 시간이 걸리는 한 지점을 떠올리게 합니다. 효과의 정량 수치는 제시하지 않고, 오늘은 이 연결을 직접 확인하는 수업임을 설명합니다.

### 03. 제조 AI: 문서·영상·계측 정보

설명 3분

0–1분: 앞선 교육의 문서 검색, 사진 품질 확인, 검사 이력 관리를 연결해서 설명합니다. 오늘은 각 기능의 결과를 한 작업 기록 안에 모으는 단계입니다.
1–2분: 문서는 해야 할 일과 기준을, 영상은 현재 보이는 상태를, 계측은 숫자와 단위를 제공합니다. 같은 숫자라도 어느 제품의 어느 위치인지 연결되어야 의미가 생깁니다.
2–3분: Physical AI는 물리 환경의 인지와 행동을 다루는 더 넓은 영역이라고 짧게 소개합니다. 이 솔루션은 작업 관찰과 지원에 초점을 두며, 현재 실습이 로봇 동작이나 설비를 직접 제어하는 것은 아닙니다. 스마트 글래스도 현장 영상을 얻는 입력 장치라는 수준에서 설명합니다.

### 04. AI Agent: 판단과 업무 실행

설명 3분

0–1분: 질문에 설명을 돌려주는 일반 대화와, 설명 이후 필요한 행동을 연결하는 Agent를 비교합니다. 예를 들어 두께가 흐리게 보인다고 끝내는 대신 해당 위치의 기준을 확인하고 작업자에게 값을 물어볼 수 있습니다.
1–2분: Agent가 사용하는 도구는 문서 조회, 기준 비교, 질문 생성, 결과 저장처럼 구체적인 기능입니다. 모든 판단을 하나의 모델이 맡을 필요는 없습니다. 숫자 범위 비교는 규칙으로 처리할 수 있습니다.
2–3분: 현재 작업 상태를 기억하는 역할을 설명합니다. 다음 장면으로 넘어갔다고 미답변 질문이 사라져서는 안 됩니다. 마지막 보고서는 그동안 쌓인 기록을 사용해야 합니다.

### 05. Dynin 솔루션: 전체 처리 구조

설명 3분

0–1분: 회사가 주는 자료에서 작업 목록, 순서, 검사 항목, 수치 범위를 준비하는 사전 설정을 설명합니다. 이후 작업자가 제품이나 작업을 선택하면 관련 정보가 연결됩니다.
1–2분: 현장에서는 카메라 또는 스마트 글래스로 장면을 받고, 관찰 결과를 해당 작업의 기준과 비교하는 구조를 목표로 합니다. 보이지 않는 항목은 추가 장면이나 작업자 확인을 요청합니다. 이것은 솔루션의 목표 업무 흐름이며 모든 조건의 현장 성능을 보장하는 설명은 아닙니다.
2–3분: 보고서는 마지막에 새로 지어내는 문서가 아니라 작업 중 모은 기준, 관찰, 질문과 답변, 증거 사진을 정리한 결과입니다. 다음 슬라이드에서 각 역할을 구분합니다.

### 06. 제조 Agent: 기능별 역할 분담

설명 3분

0–1분: 모델의 역할은 영상에서 무엇이 보이는지, 어떤 숫자가 보이는지 후보를 만드는 일이라고 설명합니다. 숫자가 읽혔다고 바로 정상 판정이 되는 것은 아닙니다.
1–2분: 제어 기능은 어떤 제품·도면·검사 위치에 해당하는지 확인하고 단위와 허용 범위를 비교합니다. 정보가 부족하면 확인 필요로 남기고 질문을 연결합니다. 기대 범위에 들어오도록 원래 숫자를 임의로 고치지 않습니다.
2–3분: 작업자의 답변도 출처가 있는 새 기록입니다. 실제 현장에서는 책임자의 검토와 승인 절차가 필요하며, 보고서 저장 버튼이 승인을 대신하지 않습니다. 교실에서는 수강생이 작업자 역할을 맡습니다.

### 07. 적용 사례(전자 조립): 작업 확인

설명 3분

0–1분: 화면의 배터리 질문을 가리키고, 손에 가린 부분을 정상이라고 추측하는 대신 확인 요청으로 남기는 이유를 설명합니다. 화면은 실제 앱 캡처이며 관찰 내용은 수업을 위해 구성한 예시입니다.
1–2분: 작업자가 방향을 확인했다고 답하면 해당 기준이 작업자 확인을 인정하는지에 따라 판정이 달라집니다. 반대로 들어가 있다고 답하면 불일치를 남깁니다. 영상만 인정하는 조건이라면 작업자 답변이 있어도 확인 필요일 수 있습니다.
2–3분: 지금은 강사 화면만 보게 하고, 질문 확인·답변 버튼의 실제 조작은 전자 실습에서 진행한다고 알립니다. 합격 개수보다 어떤 근거로 판단했는지를 읽는 것이 목표입니다.

### 08. 적용 사례(계측 검사): 측정값 확인

설명 3분

0–1분: 숫자를 잘 읽는 문제와 읽은 숫자를 판정하는 문제를 구분합니다. 표준형과 정밀형은 제품과 허용 범위가 다르며, 같은 40.02 mm가 다른 판정으로 연결됩니다.
1–2분: 표에서 40.02가 표준형 상한 40.10보다 작고 정밀형 상한 40.01보다 크다는 점을 같이 계산합니다. 모델이 합격 여부를 추측할 필요 없이 숫자와 규칙을 정확히 연결하면 됩니다.
2–3분: C의 한 자리가 가려지면 최초 표시 5.?8 mm를 남기고 답변으로 확인값을 받습니다. 수업에서는 5.78 mm를 작업자 역할로 입력하며 실제 장비를 읽었다고 설명하지 않습니다.

### 09. 실습 범위: 예시 자료와 실행 기능

설명 2분

0–1분: 화면의 강의용 예시 표시를 설명합니다. 앱은 라이브 AI를 호출하는 제품 시연이 아니라 동일한 상황에서 조건을 바꾸어 업무 흐름을 이해하는 실습입니다. 준비된 관찰에 대한 판단을 직접 확인할 수 있습니다.
1–2분: 문서에서 정보를 추출하고, 입력값을 검사하고, 보고서를 만드는 부분은 실제 동작입니다. 현장 정확도나 로봇 제어 성능을 검증하는 수업은 아닙니다. 이제부터는 수강생이 함께 접속하고 자료를 여는 25분 준비 활동으로 전환합니다.

### 10. 실습 준비: 사이트 접속

설명 1.5분 + 직접 조작 3.5분

설명 1분30초: 화면의 링크를 강의 공지에 붙여 넣고 실습 사이트를 엽니다. GitHub 저장소의 코드 화면이 아니라 실습 페이지에 접속해야 합니다. PC 브라우저 사용을 권장하고, GitHub 로그인·Python 설치·API 키는 요구하지 않습니다.
활동 3분30초: 모두 첫 화면의 전자 조립 카드와 계측 카드를 확인하게 합니다. 아직 실습을 시작하지 않고 브라우저 탭을 유지합니다. 주소를 즐겨찾기에 넣은 사람은 옆 사람의 접속을 돕습니다. 접속이 안 되면 주소의 저장소 경로와 마지막 슬래시를 확인하고 강사가 공지 링크를 다시 제공합니다.

### 11. 실습 준비: 강의 자료 다운로드

설명 1.5분 + 직접 조작 3.5분

설명 1분30초: 실습 탭을 유지하고 자료실을 새 탭으로 엽니다. 필수 파일은 설명 슬라이드 PDF와 예제 자료 묶음 ZIP 두 개입니다. PPTX는 발표용, 전체 실습팩은 인터넷이 없는 운영용이라고 구분합니다. 대용량 전체팩 다운로드로 수업을 지연시키지 않습니다.
활동 3분30초: PDF를 저장해 첫 페이지를 열고, 예제 ZIP을 받아 압축을 풉니다. Windows는 압축 풀기 기능, macOS는 ZIP 열기를 사용하도록 안내합니다. 압축 안의 파일을 바로 편집하지 않게 합니다. 자료 다운로드가 제한된 PC는 우선 앱 내 기본 자료로 진행하고 강사가 파일을 전달합니다.

### 12. 실습 자료: 파일별 용도

설명 1분 + 직접 조작 2분

설명 1분: 다운로드한 자료가 모두 같은 용도가 아니라는 점을 설명합니다. SOP와 CSV는 입력, 도면은 검사 위치와 조건을 확인할 자료, 검수조서는 최종 산출물 예제입니다. 입력 폴더를 공개하고 파일 이름을 확인합니다.
활동 2분: 전자 SOP PDF와 표준형 도면 PDF를 각각 열고, CSV의 A/B/C 행을 확인합니다. CSV를 Excel에서 저장하면 서식이 바뀔 수 있으므로 지금은 보기만 하게 합니다. 앱에는 같은 예제가 기본 제공되어 있어 이 파일들을 다시 업로드할 필요가 없습니다.

### 30. 실습 2(계측 검사): 제품별 기준 비교

설명 1.5분

표준형 결과와 진행 JSON을 먼저 저장합니다. ‘다른 제품 선택’은 제품·도면 화면으로 이동하는 버튼입니다. 여기서 BSH-2630-P의 ‘정밀형 플랜지 부시’를 눌러 새 제품을 선택하고 기존 최근 세션을 바꾸는 알림을 확인합니다. 두 제품 모두 개정 A지만 제품·도면·시편 ID가 다릅니다. 표준형 측정값을 자동으로 이어 쓰지 않으며 ‘검사 기준 불러오기 · 정보 구축’부터 다시 시작합니다. 새 장면에 같은 예시 숫자가 준비되어 있으나 새로운 기록입니다. 5.78 답변까지 제출하면 길이 B만 범위 밖입니다. 비교표의 범위 단위는 모두 mm입니다.

### 31. 실습 2(계측 검사): 검수조서 저장

설명 1분

측정 화면의 마지막 ‘검수조서 만들기’는 먼저 검사 결과로 이동하고, 결과 화면에서 같은 이름의 버튼을 한 번 더 누르면 저장 화면입니다. ‘검수조서 저장’으로 단독 HTML을 받습니다. 결과 보고서는 ‘도면 포함 HTML 저장’, 표는 ‘검사 CSV’, PDF는 ‘인쇄 / PDF 저장’을 사용합니다. 서명과 실제 검사일을 자동 승인 사실처럼 채우지 않습니다. 정밀형의 불일치가 보고서에서도 유지되는지 확인합니다. 표준형과 정밀형을 파일명으로 구분합니다.

### 32. 결과 저장과 진행 복구

설명 1분

현재 실습을 ‘진행 내보내기’로 저장하고 브라우저를 새로고침합니다. 같은 주소·브라우저에서는 저장 상태가 복구됩니다. 다른 주소나 PC에서는 JSON을 ‘가져오기’로 불러옵니다. 보고서 HTML은 실습 앱의 백업 파일이 아니므로 가져오기에 넣지 않습니다. 보고서의 ‘실행 JSON’도 진행 백업에 사용할 수 있습니다. 새 제품을 고르기 전 백업하는 습관을 강조합니다. SQLite 파일은 구축한 표와 기록을 확인하는 추가 산출물로 소개하되, SQL을 다루는 활동은 필수가 아닙니다.

### 33. 현장 업무 적용 검토

설명 2분

2인 또는 소그룹으로 진행합니다. 실제 회사 자료를 앱에 업로드하지 않고 작업 이름과 필요한 정보 종류만 활동지에 적습니다. 답변 예: ‘부시 외경 검사 / 도면 개정과 외경 범위 / 제품·시편·A 위치 / 표시가 가려지면 값과 단위 재확인 / 최초 표시와 확인값·판정 보관’. 조별로 한 작업을 선택하고 자료→대상→질문→판정→기록을 5칸에 적습니다. 발표 때는 자동화 효과를 수치로 추정하기보다 누가 기준을 확인하고 미확인 항목을 처리할지 설명하게 합니다.

### 34. 실습 결과 정리 및 제출

설명 1분

수강생에게 ‘장면이 끝났는데 확인이 남을 수 있는가’, ‘5.?8을 왜 그대로 남기는가’, ‘40.02가 제품에 따라 왜 다른 판정인가’를 묻습니다. 기대 답은 각각 ‘미답변·미검토가 남기 때문’, ‘원기록과 확인 근거를 구분하기 위해’, ‘적용하는 허용 범위가 다르기 때문’입니다. 제출 폴더에서 전자 기본·변경 보고서, 표준형·정밀형 검수조서, JSON, 이유 문장과 업무 흐름을 확인합니다. 모든 산출물은 강의용 예시이며 오늘의 결과를 실제 제품 승인이나 AI 성능 지표로 해석하지 않습니다.

## 결과 파일 구분

권장 파일명은 전자_기본.html, 전자_비교.html, 계측_표준형.html, 계측_정밀형.html, 실습진행.json, 판정이유.txt입니다. 앱이 자동으로 해당 이름을 부여하는 것은 아니므로 저장 후 구분합니다. 보고서 HTML은 결과 확인용이며 진행 복원은 JSON을 사용합니다.
