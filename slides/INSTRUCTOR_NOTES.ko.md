# 강사용 진행 메모 · 제조 AI Agent 실습

전자 조립과 제품 계측을 통해 **자료 → 관찰 → 질문 → 판정 → 기록**의 흐름을 배우는 4시간 수업입니다. 수강생은 코드를 작성하지 않고 앱의 버튼과 입력란을 사용합니다. 슬라이드 원문은 [content.json](content.json)에 있습니다. 화면 문구는 일반 강의 제목과 명사형 불릿으로 구성합니다. 아래의 도입 발화와 설명은 강사가 말로 전달할 문장이므로 서술형을 유지합니다.

## 강사가 먼저 기억할 범위

수강생 화면과 산출물의 표시는 **강의용 예시**입니다. 공개 전자 조립 영상·사진에 준비한 관찰 사건을 연결하고, 제품 계측은 가상 회사의 제품·도면·장비 표시를 사용합니다. 오늘의 답변은 수강생의 작업자 역할 답변입니다. 실제 모델의 분석 결과, 실제 촬영 작업자의 확인, 실측 인증, 생산 승인이 아닙니다.

브라우저는 템플릿 SOP PDF의 텍스트를 실제로 추출하고 CSV의 기준을 검증하여 SQLite를 구성합니다. 질문·답변·허용 범위·판정·보고서 생성도 실제 동작입니다. 임의 스캔 도면을 이해하는 OCR이나 모델, 실시간 음성 인식은 실행하지 않습니다. 질문 듣기는 브라우저의 읽어 주기 기능입니다.

기존 실제 모델 응답과 예전 사례는 강사용 참고 경로에 보존되어 있습니다. 이 수업은 홈의 기본 전자 조립 및 계측 경로만 사용합니다. 새로운 모델 실행, GPU 사용, 외부 게시를 포함하지 않습니다. 비공개 회사 자료는 업로드하거나 보여 주지 않습니다.

## 수업 전 준비

1. Python 3를 준비하고 전체 실습팩을 풉니다. macOS/Linux에서는 프로젝트 폴더에서 아래 서버를 실행합니다. Windows에서는 `py -3 scripts/serve.py`를 사용합니다. 강사가 서버를 준비했다면 학생에게는 해당 주소만 제공합니다.

   ```sh
   python3 scripts/serve.py
   ```

   로컬 실행 주소는 `http://127.0.0.1:8921/`입니다. 전체 앱의 `index.html`을 더블클릭해 실행하지 않습니다.

2. 강의 PC에서 전자 조립의 여섯 장면 사진, 계측의 A/B/C 도해, 문서 ‘정보 구축’, HTML 다운로드를 한 번 확인합니다. 원본 영상 재생이 어려워도 준비된 사진으로 수업을 진행할 수 있습니다. 영상 재생 여부를 새 검사 기록으로 설명하지 않습니다.
3. ‘질문 듣기’의 한국어 음성과 스피커를 확인합니다. 소리가 나오지 않으면 ‘질문 확인’ 버튼으로 진행합니다. 마이크 입력은 사용하지 않습니다.
4. 브라우저에서 보고서 HTML을 저장하고 다시 여는 과정을 확인합니다. 개별 보고서는 사진·도면·글꼴이 포함되어 단독으로 열립니다. PDF는 ‘인쇄 / PDF 저장’을 사용합니다.
5. 수강생에게 결과 폴더를 만들게 합니다. 기본 결과와 비교 결과의 기본 다운로드 이름이 같을 수 있으므로 이름을 구분해 저장하도록 안내합니다.

권장 제출 이름은 `전자_기본.html`, `전자_비교.html`, `계측_표준형.html`, `계측_정밀형.html`, `실습진행.json`, `판정이유.txt`입니다. 앱이 이 이름을 자동으로 부여하는 것은 아니며 학생이 보관할 때 구분합니다.

## 4시간 운영표

슬라이드는 **총 35분 설명용**이며 각 실습 직전에 나누어 사용합니다. 35분 설명을 처음에 모두 진행한 뒤 같은 설명을 다시 반복하는 시간표가 아닙니다. 설명 35분 + 직접 조작·비교·토의 175분 = 학습 210분, 휴식 30분을 더해 총 240분입니다.

## 전체 흐름 도식 설명

왼쪽부터 **SOP PDF + CSV → 회사·작업·대상·기준 → 장면과 관찰 → 확인 질문 ↔ 작업자 답변 → 기준별 판정 → 보고서·검수조서**로 읽습니다. PDF/CSV에서 SQLite로 가는 화살표에는 ‘실제 문서 처리’, 장면의 관찰에는 ‘강의용 예시’, 답변에는 ‘학생이 직접 입력’을 붙여 구분합니다.

답변 또는 적용 기준에서 판정으로 되돌아가는 화살표는 ‘원기록을 보존하고 재판정’입니다. 모든 관찰에서 질문이 필요한 것은 아닙니다. 정보가 충분하면 기준과 직접 비교하고, 부족한 경우 질문합니다. 다음 작업으로 이동하는 화살표와 이전 검사 항목이 충족되는 것은 별개입니다.

## 슬라이드별 발화·화면 조작·확인 포인트

아래 시간은 슬라이드 설명 시간만 계산한 값입니다. 조작 활동은 위 운영표에 별도로 배정되어 있습니다. ‘강의용 예시’라는 말을 처음에 분명히 한 뒤, 관찰과 실제 입력이 혼동될 지점에서 다시 짚습니다.

### 01. 제조 AI Agent 실습 · 설명 1분

**도입 발화:** “내가 바꾼 답변과 기준이 검사 결과에 어떻게 남는지 직접 확인합니다.”

오늘의 목표를 세 문장으로 소개합니다. 코드를 작성하거나 모델을 설치하는 수업이 아니라, 준비된 앱에서 제조 업무의 입력·확인·판정·기록을 경험하는 수업입니다. 화면의 ‘강의용 예시’ 표시를 먼저 가리킵니다. 두 실습의 마지막 보고서 모습을 짧게 보여 주어 완성할 결과를 알게 합니다.

화면에서 확인할 내용:

- 전자 조립: 가려진 배터리 방향의 질문과 답변
- 계측 검사: 불확실한 측정값 확인과 허용 범위 비교
- 실습 산출물: 사진·도면·판정 근거를 포함한 보고서와 검수조서

### 02. 강의 구성 · 설명 1분

**도입 발화:** “오늘은 설명 35분과 직접 조작·비교·토의 175분, 휴식 30분으로 진행합니다.”

설명 슬라이드 24장을 한 번에 모두 읽지 않습니다. 01–05를 설명한 뒤 접속하고, 06–09를 보여 준 뒤 전자 실습을 시작하는 식으로 분산합니다. 표의 시간은 수업 시작부터의 경과 시간입니다. 전체 강의 240분, 실제 학습 210분이며 설명 35분은 210분 안에 포함됩니다. 활동 속도에 따라 비교 활동의 반복 횟수를 조절합니다.

화면에서 확인할 내용:

- 진행 순서: 전체 흐름과 접속 → 전자 조립 → 계측 검사
- 설명 35분: 각 실습 직전 분산 진행
- 직접 조작·비교·토의 175분 + 휴식 10분씩 3회
- 제출물: 결과 파일과 판정 변경 이유

### 03. 제조 AI Agent: 처리 구조 · 설명 2분

**도입 발화:** “Agent의 흐름을 ‘다음에 무엇을 확인하고 기록할지’로 이해합니다.”

SOP는 작업 절차서, CSV는 표 파일이라고 풀어 설명합니다. 일반적인 AI 역할은 이미지·문장에서 관찰 후보를 제안하는 것이고, 업무 흐름은 이 후보를 제품과 기준에 연결하고 필요한 질문과 기록을 이어 가야 합니다. 오늘은 그 관계를 배우기 위해 관찰 후보를 미리 준비했습니다. 화살표를 왼쪽부터 따라가고, 답변이나 기준이 바뀌면 판정이 다시 계산되는 화살표를 짚습니다.

화면에서 확인할 내용:

- 회사 자료: 제품·작업 순서·검사 기준 등록
- 관찰과 질문: 관찰 내용 기록과 부족한 정보 확인
- 판정: 대상·시점·증거·기준의 비교
- 보고서: 판정에 사용한 사진·값·답변·이력 보관

### 04. 실습 범위와 자료 구성 · 설명 2분

**도입 발화:** “관찰 예시는 준비되어 있고, 내 선택에 따른 기록과 결과는 실제로 바뀝니다.”

‘실제 처리’는 실제 공장 검사라는 뜻이 아니라 소프트웨어 기능이 실제 실행된다는 뜻입니다. SQLite는 회사·작업·검사 기준을 표로 저장하는 작은 데이터베이스라고 설명합니다. 오늘 자료는 정해진 템플릿을 읽으며 임의의 스캔 도면을 자동 이해하지 않습니다. 기본 실습에는 실시간 모델·OCR·음성 인식 호출이 없습니다. 질문 듣기는 브라우저의 읽어 주기이고 답변은 버튼이나 텍스트 입력입니다. 정확도·속도 수치나 실제 제품의 품질 승인으로 설명하지 않습니다.

화면에서 확인할 내용:

- 문서 처리: PDF 텍스트 추출 + CSV 검증 → SQLite 구성
- 강의용 예시: 전자 장면의 관찰 설명, 제품 도면·계측 표시
- 사용자 입력: 질문 답변, 확인값, 실습 적용 기준
- 결과 처리: 판정 재계산, 이력 보존, 보고서 파일 생성

| 준비 자료 | 브라우저 실행 기능 |
| --- | --- |
| 공개 전자 조립 영상·사진 | 질문 확인과 답변 기록 |
| 작성한 관찰 사건·계측 도해 | 값·단위·기준 비교 |
| 템플릿 SOP PDF·CSV | 문서 추출·SQLite·보고서 생성 |

### 05. 실습 환경 접속 · 설명 1분

**도입 발화:** “강사가 안내한 주소를 열고 ‘강의용 예시’ 표시를 확인하세요.”

수강생에게는 강사가 제공한 주소를 안내합니다. 각자 실행할 때는 Python 3를 준비하고 전체 ZIP을 풉니다. 프로젝트 폴더에서 macOS/Linux는 python3 scripts/serve.py, Windows는 py -3 scripts/serve.py를 실행하고 http://127.0.0.1:8921/을 엽니다. 전체 앱은 HTML 파일 더블클릭으로 열지 않습니다. 반면 저장한 개별 HTML 보고서는 더블클릭으로 열 수 있습니다. API 키, GPU, 모델 설치는 필요 없습니다. 이어지는 접속 활동 13분 동안 전원이 홈 화면을 열고 저장 폴더를 만들게 합니다.

화면에서 확인할 내용:

- 시작 버튼: ‘전자 조립 실습 시작’
- 준비물: 브라우저, 결과 파일 저장 폴더
- 음성 미지원 시 ‘질문 확인’ 버튼 사용
- 영상 재생 불가 시 준비된 장면 사진 사용

### 06. 실습 1(전자 조립): 데이터 변환 · 설명 1.5분

**도입 발화:** “가상의 다온에듀테크 · 바람빛 회로 키트 한 세트를 조립합니다.”

홈에서 ‘전자 조립 실습 시작’을 누릅니다. 문서의 ‘열기’로 SOP를 보여 주고 준비 부품, 작업 순서, 검사 조건을 짚습니다. CSV는 ‘검사 기준 CSV 보기 / 편집’을 펼칩니다. ‘정보 구축’을 누른 후 edu-daon, ELEC-DEMO-001과 여섯 기준을 확인합니다. 추출 텍스트와 실제 SQLite 조회 결과를 펼쳐 파일 내용이 표로 바뀐 것을 보여 줍니다. SQL 문법은 설명하지 않아도 됩니다. 준비된 이벤트와 기준의 의미가 연결되어 있으므로 항목명·대상·정책을 임의 문구로 교체하는 활동은 하지 않습니다.

화면에서 확인할 내용:

- SOP PDF와 검사 기준 CSV의 내용 확인
- ‘정보 구축’ → 회사·공정·검사 기준 6개 확인
- ‘PDF에서 실제로 추출한 텍스트’와 원문 비교
- ‘실제 SQLite 조회 결과’ 확인 → ‘작업 설정으로’ 이동

### 07. 실습 1(전자 조립): 작업 기록 · 설명 1.5분

**도입 발화:** “준비 → 회로 → 프로펠러 → 배터리 → 스위치 → 최종 확인”

작업 설정에서 여섯 작업과 여섯 기준을 확인한 뒤 ‘작업 시작하기’를 누릅니다. 첫 화면에는 준비 사진이 보여도 기록 전일 수 있습니다. ‘준비 장면 확인하기’를 누르면 첫 기록과 체크리스트가 바뀝니다. 이후 버튼 이름은 ‘다음 장면 확인하기’입니다. 작은 장면 버튼은 미리보기이며 기록을 진행하지 않습니다. 원본 영상 재생도 기록을 바꾸지 않습니다. 두 번 진행한 뒤 수강생의 체크리스트가 함께 변하는지 확인합니다.

화면에서 확인할 내용:

- 작업 순서 확인 후 ‘작업 시작하기’ 선택

### 19. 실습 2(계측 검사): 허용 범위 변경 · 설명 2분

**도입 발화:** “표준형 B의 실습 상한을 40.10 → 40.01 mm로 바꿔 보세요.”

‘허용 범위를 바꾸어 비교’에서 B 전체 길이 폼만 수정합니다. 하한 39.90은 유지하고 상한만 40.01로 바꿉니다. 범위는 하한과 상한을 포함하여 비교합니다. 40.02가 40.01보다 0.01 크므로 불일치입니다. 화면에 원본 도면 기준과 실습 적용 기준이 함께 표시되는지 확인합니다. 이것은 수업의 조건 비교이며 도면 개정이나 생산 기준 승인을 실행하는 기능은 아닙니다. 비교 파일을 저장한 뒤 40.10으로 되돌립니다.

화면에서 확인할 내용:

- 검사 결과의 B ‘실습 상한 (mm)’에 40.01 입력
- ‘새 기준 적용’ → B 불일치
- 도면 원래 기준 39.90–40.10 mm 보존
- 상한 40.10 복원 시 B 충족

| B 측정값 | 실습 적용 범위 | 판정 |
| --- | --- | --- |
| 40.02 mm | 39.90–40.10 mm | 충족 |
| 40.02 mm | 39.90–40.01 mm | 불일치 |

### 20. 실습 2(계측 검사): 제품별 기준 비교 · 설명 1.5분

**도입 발화:** “같은 예시 숫자라도 제품이 달라지면 검사 기준을 새로 확인해야 합니다.”

표준형 결과와 진행 JSON을 먼저 저장합니다. ‘다른 제품 선택’은 제품·도면 화면으로 이동하는 버튼입니다. 여기서 BSH-2630-P의 ‘정밀형 플랜지 부시’를 눌러 새 제품을 선택하고 기존 최근 세션을 바꾸는 알림을 확인합니다. 두 제품 모두 개정 A지만 제품·도면·시편 ID가 다릅니다. 표준형 측정값을 자동으로 이어 쓰지 않으며 ‘검사 기준 불러오기 · 정보 구축’부터 다시 시작합니다. 새 장면에 같은 예시 숫자가 준비되어 있으나 새로운 기록입니다. 5.78 답변까지 제출하면 길이 B만 범위 밖입니다. 비교표의 범위 단위는 모두 mm입니다.

화면에서 확인할 내용:

- 진행 저장 후 ‘다른 제품 선택’ → ‘정밀형 플랜지 부시’ 선택
- BSH-2630-P · DR-BSH-2630-P · EDU-BSH-P-001
- 새 제품의 정보 구축과 A/B/C 측정값 재기록
- 5.78 mm 답변 후: 충족 2 / B 길이 불일치 1

| 위치 · 예시값 | 표준형 범위 | 정밀형 범위 |
| --- | --- | --- |
| A · 26.30 mm | 26.10–26.50 | 26.25–26.35 |
| B · 40.02 mm | 39.90–40.10 | 39.99–40.01 |
| C · 확인값 5.78 mm | 5.70–5.90 | 5.75–5.85 |

### 21. 실습 2(계측 검사): 검수조서 저장 · 설명 1분

**도입 발화:** “검수조서를 만든 뒤 저장하여 제품과 도면, 측정값을 함께 확인합니다.”

측정 화면의 마지막 ‘검수조서 만들기’는 먼저 검사 결과로 이동하고, 결과 화면에서 같은 이름의 버튼을 한 번 더 누르면 저장 화면입니다. ‘검수조서 저장’으로 단독 HTML을 받습니다. 결과 보고서는 ‘도면 포함 HTML 저장’, 표는 ‘검사 CSV’, PDF는 ‘인쇄 / PDF 저장’을 사용합니다. 서명과 실제 검사일을 자동 승인 사실처럼 채우지 않습니다. 정밀형의 불일치가 보고서에서도 유지되는지 확인합니다. 표준형과 정밀형을 파일명으로 구분합니다.

화면에서 확인할 내용:

- 제품·도면 개정·시편·A/B/C 위치 확인
- 원래 범위·적용 범위·기록값·판정 대조
- 최초 후보·작업자 확인값·질문 답변·장면 확인
- 표준형·정밀형 검수조서의 구분 저장

### 22. 결과 저장과 진행 복구 · 설명 1분

**도입 발화:** “읽을 결과물과 이어 할 진행 파일을 함께 저장하세요.”

현재 실습을 ‘진행 내보내기’로 저장하고 브라우저를 새로고침합니다. 같은 주소·브라우저에서는 저장 상태가 복구됩니다. 다른 주소나 PC에서는 JSON을 ‘가져오기’로 불러옵니다. 보고서 HTML은 실습 앱의 백업 파일이 아니므로 가져오기에 넣지 않습니다. 보고서의 ‘실행 JSON’도 진행 백업에 사용할 수 있습니다. 새 제품을 고르기 전 백업하는 습관을 강조합니다. SQLite 파일은 구축한 표와 기록을 확인하는 추가 산출물로 소개하되, SQL을 다루는 활동은 필수가 아닙니다.

화면에서 확인할 내용:

- HTML·PDF: 결과와 근거 확인용 문서
- 검사 CSV: 표 형식의 검사 기록
- ‘진행 내보내기’ / ‘실행 JSON’: 실습 진행 백업
- 같은 주소 새로고침 또는 ‘가져오기’로 복구

### 23. 현장 업무 적용 검토 · 설명 2분

**도입 발화:** “조립·외관 확인·치수 검사 중 익숙한 한 작업을 고릅니다.”

2인 또는 소그룹으로 진행합니다. 실제 회사 자료를 앱에 업로드하지 않고 작업 이름과 필요한 정보 종류만 활동지에 적습니다. 답변 예: ‘부시 외경 검사 / 도면 개정과 외경 범위 / 제품·시편·A 위치 / 표시가 가려지면 값과 단위 재확인 / 최초 표시와 확인값·판정 보관’. 조별로 한 작업을 선택하고 자료→대상→질문→판정→기록을 5칸에 적습니다. 발표 때는 자동화 효과를 수치로 추정하기보다 누가 기준을 확인하고 미확인 항목을 처리할지 설명하게 합니다.

화면에서 확인할 내용:

- 자료: 필요한 작업지시서와 검사 기준
- 대상: 제품·개정·시편·검사 위치의 구분 방법
- 확인: 부족한 정보, 질문 대상과 질문 내용
- 기록: 판정 근거와 미확인 사항의 보관 항목

### 24. 실습 결과 정리 및 제출 · 설명 1분

**도입 발화:** “어떤 대상에 어떤 기준과 근거를 적용했는지 말할 수 있나요?”

수강생에게 ‘장면이 끝났는데 확인이 남을 수 있는가’, ‘5.?8을 왜 그대로 남기는가’, ‘40.02가 제품에 따라 왜 다른 판정인가’를 묻습니다. 기대 답은 각각 ‘미답변·미검토가 남기 때문’, ‘원기록과 확인 근거를 구분하기 위해’, ‘적용하는 허용 범위가 다르기 때문’입니다. 제출 폴더에서 전자 기본·변경 보고서, 표준형·정밀형 검수조서, JSON, 이유 문장과 업무 흐름을 확인합니다. 모든 산출물은 강의용 예시이며 오늘의 결과를 실제 제품 승인이나 AI 성능 지표로 해석하지 않습니다.

화면에서 확인할 내용:

- 전자 조립: 기본·변경 보고서와 판정 변경 이유
- 계측 검사: 표준형·정밀형 검수조서와 B 판정 비교
- 최초 관찰과 작업자 확인값의 구분 확인
- 진행 JSON 저장과 현장 업무 흐름 한 장 제출

## 활동 진행과 예상 결과

### 활동 A · 전자 조립의 답변과 기준

준비·회로·프로펠러·배터리·스위치·최종 확인의 여섯 장면을 모두 기록한 상태에서 비교합니다. 한 조건만 바꿔 원인을 분리합니다.

| 활동 | 실제 조작 | 기대 결과 | 수강생이 설명할 점 |
|---|---|---|---|
| 기본 완료 | 질문 확인 → 방향을 확인했습니다 → 남은 장면 기록 | 충족 6 | 배터리는 작업자 확인을 별도 근거로 인정 |
| 미답변 | 답하지 않고 마지막 장면까지 진행 | 충족 5 + 확인 필요 1 | 작업이 끝나도 질문은 미해결 |
| 증거 기준 변경 | 시각 증거만 인정 → 기준 적용 · 재판정 | 충족 5 + 확인 필요 1 | 답변이 사진 증거가 되지는 않음 |
| 반대 답변 | 작업자 직접 확인도 인정 적용 → 답변 다시 확인하기 → 질문 확인 → 반대로 들어가 있습니다 | 충족 5 + 불일치 1 | 부정 답변도 기록과 결과에 반영 |

긍정 답변 이후 재확인을 시작하면 이전 답변이 이력에 남아도 현재 확인 요청은 해결 전입니다. 다시 질문을 확인하고 답변하는 순서를 빠뜨리지 않습니다. 최종 장면으로 진행한다고 반대 답변이나 미해결 요청이 사라지지 않습니다.

### 활동 B · 계측의 숫자와 범위

표준형에서 A `26.30 mm`, B `40.02 mm`, C 최초 후보 `5.?8 mm`를 기록한 뒤 비교합니다. C의 작업자 답변은 수강생이 제출해야 기록됩니다.

| 조건 | A | B | C | 기대 결과 |
|---|---|---|---|---|
| 표준형, C 답변 전 | 26.30 | 40.02 | 확정값 없음 | 충족 2 + 확인 필요 1 |
| 표준형, C에 5.78 mm 답변 | 26.30 | 40.02 | 5.78 | 충족 3 |
| 표준형, C에 6.08 mm 답변 | 26.30 | 40.02 | 6.08 | 충족 2 + C 불일치 1 |
| 표준형, C에 578 mm 답변 | 26.30 | 40.02 | 578 | 충족 2 + C 불일치 1, 소수점 자동 보정 없음 |
| 표준형, B 상한만 40.01로 변경, C 5.78 | 26.30 | 40.02 | 5.78 | 충족 2 + B 불일치 1 |
| 정밀형 새 실습, C에 5.78 mm 답변 | 26.30 | 40.02 | 5.78 | 충족 2 + B 불일치 1 |

모든 숫자의 단위는 mm입니다. `inch`는 이 실습의 단위 검증에서 거부되며 단위를 자동 환산하지 않습니다. `C 확인값 다시 입력`을 누르면 과거 답변을 남긴 채 새 확인 대기 상태가 됩니다. 새 답변을 제출하기 전에는 보고서도 검사가 완료된 것으로 표시하지 않아야 합니다.

표준형 B의 실습 상한 변경과 정밀형 제품 선택은 다른 활동입니다. 전자는 같은 표준형 도면을 보존하고 실습에서 적용할 범위만 바꿉니다. 후자는 제품·도면·시편이 다른 새 실습을 시작합니다. 두 활동 모두 40.02라는 숫자를 마음대로 수정하지 않습니다.

### 활동 C · 현장 업무를 5칸으로

각 조는 아래 질문에 한 줄씩 답합니다. 업무명과 정보 종류만 작성하고 비공개 문서나 영상은 가져오지 않습니다.

| 칸 | 적을 내용 | 답변 예 |
|---|---|---|
| 자료 | 작업 순서와 기준은 어디에 있는가? | 작업지시서, 도면 개정, 검사 기준표 |
| 대상 | 무엇의 어느 부분을 확인하는가? | 제품번호, 시편번호, A 외경 |
| 관찰·질문 | 불확실하면 무엇을 다시 물을까? | 표시된 값과 단위를 다시 확인 |
| 판정 | 어떤 범위·증거를 인정할까? | 해당 제품의 허용 범위, 승인된 확인 방법 |
| 기록 | 결과와 함께 무엇을 남길까? | 최초 표시, 확인 답변, 현재 판정, 미확인 사항 |

발표 예: “부시 외경을 검사할 때 제품·도면 개정·시편을 연결하고, 표시가 가려지면 값과 단위를 물어 최초 표시와 확인값을 함께 남기겠습니다.” 실제 배치 전에는 담당자의 기준 확인, 장비·측정 절차, 역할과 승인 과정 등이 별도로 정해져야 한다고 설명합니다. 오늘 수업만으로 현장 성능이나 적용 타당성을 확정하지 않습니다.

## 종료 확인

수강생이 다음 네 가지를 설명하면 수업의 학습 목표를 확인할 수 있습니다.

- 작업 진행과 검사 완료는 다르며, 미해결 질문은 마지막 장면에서도 남는다.
- 같은 관찰·답변이라도 인정하는 증거 기준이 달라지면 판정이 바뀔 수 있다.
- 최초 후보와 작업자 확인값을 구분하고, 제품·위치·단위를 연결해야 한다.
- 값은 유지하고 적용 기준을 바꾸어 비교하며, 근거와 이력을 보고서에 남긴다.

제출물은 전자 기본·비교 보고서, 표준형·정밀형 검수조서, 진행 JSON, 판정 변화의 이유 문장, 우리 업무 흐름입니다. 검사 CSV와 SQLite는 추가 산출물로 받습니다. 실제 모델 정확도나 생산 승인 여부는 이 수업의 평가 항목이 아닙니다.
